# 055 · контракт снимка завершённого сеанса шумомера (для блока 2)

Код: `src/core/noiseSession.ts`, тип `NoiseSessionV1`. Функции:

- `createNoiseSession(meter, meta, capture, model)` — снимок;
- `checkNoiseSession(value)` — проверка формы и длин;
- `restoreNoiseSession(session)` — просмотр теми же запросами, что и живая история;
- `noiseSessionBytes(session)` — объём массивов.

Блок 1 только определяет и тестирует контракт: в интерфейсе снимок не создаётся и не экспортируется. Хранилище, библиотека, сравнение и импорт — блок 2.

## Принципы

- **Исходные данные** — линейные суммы и счётчики: отсчёты, Σx², энергия и мощность × время, пики. **Производные** — всё, что выводится при просмотре: уровни dB, окна Leq 1/10/60 с, Leq с начала, доли полос, цвета и шкала спектрограммы, выбор интервала. Производные не сохраняются, поэтому новые представления и исправления отображения не требуют миграции.
- Непрерывный PCM не сохраняется. Сырые спектры — только PSD Z по бинам на момент остановки, четыре периода (≈0,5 МБ).
- Массивы типизированные (`Float64Array`, `Float32Array`, `Uint32Array`, `Uint16Array`, `Uint8Array`) и проходят structured clone без преобразования (IndexedDB). Кодирование в JSON для файлового экспорта и импорта выбирает блок 2.
- Шкала времени — отсчёты от начала сеанса. Секунды = отсчёты / `sampleRate`. Пропуски занимают своё время. `audioStartMs` — приблизительная привязка к часам устройства.
- Варианты «с поправкой» посчитаны при записи с профилем, закреплённым за сеансом. Его снимок хранится целиком. Новые версии и архив профиля снимок не меняют.
- Неизвестные `kind` или `version` — ошибка, а не попытка чтения. Будущие версии добавляют поля с новым номером `version`; чтение v1 сохраняется.

| `meta` | `name`, `createdAt` (ISO UTC), `audioStartMs`, `stopReason`, `manualCheck`, `build {sha, time}` | — |
| `capture` | Диагностика тракта без `deviceId`, `groupId` и названия входа: `backend`, `sampleRate`, `constraintsFallback` и прочие поля диагностики | как в schema 2 |
| `settings` | `sampleRate`, `blockSamples` 4096, `fftSize` 32768, `hopSamples` 16384, `window` 'periodic Hann', столбцы 1 и 10 с, кольцо 600 с, предел 43200 с, порядок вариантов, границы полос спектрограммы и шести полос | Гц, отсчёты, с |
| `calibration` | `null` или `{profile, model, maxBoostDb, outsideRange: 'uncorrected'}` | дБ |
| `units` | Текстовое описание единиц, ниже | — |
| `totals` | `endSamples`, `blocks`, `missingBlocks`, `clippedBlocks`, `sumSquares`, `samplePeak`, `spectralFrames`, `weightedPower {A, C}` (средняя мощность A/C по кадрам — Leq сеанса до логарифма) | FS², FS |
| `blocks` | Точки A по блоку 4096 в колонках: `next` (номер следующего блока; конец = next·4096/fs), `rms`, `rms1s` (dBFS, NaN — нет значения), `peakBin` (0xFFFF — нет), `flags` (1 — полное окно 1 с, 2 — клиппинг), `missingBefore` | dBFS, бины 4096 |
| `timeline.levels` | Столбцы 1 с, длина L = ⌈end / fs⌉: `pcm` (принятые отсчёты), `z` (Σx²), `peak` (max\|x\|), `spec` (отсчёты, учтённые спектром), `a`, `c` (Σ мощность × отсчёты), `energy` (L × 6 полос × V, Float32) | отсчёты, FS²·отсчёт, FS |
| `timeline.coarse` | Столбцы 10 с: `spec`, `energy` (M × полосы спектрограммы × V) | отсчёты, FS²·отсчёт |
| `timeline.fine` | Последние кадры (≤ 10 мин) по времени: `ends` (конец hop), `power` (F × полосы × V, средняя мощность полосы кадра), `dropped` (вытесненные кадры) | отсчёты, FS² |
| `spectra` | `now`, `10`, `60`, `session`: `seconds` и `psd` Z по бинам (16385) | с, FS²/Гц |

Порядок вариантов в `energy` и `power`: Z, A, C исходные (V = 3), затем Z, A, C с поправкой (V = 6, только при `calibration`). A/C и поправка для `spectra` выводятся умножением PSD Z на коэффициенты бина: `weightPower` и `powerGains` профиля.

### Единицы (`NOISE_SESSION_UNITS`)

- PCM — цифровая шкала, полная амплитуда 1 (FS).
- Мощность — FS², средний квадрат. 10·log10 — dBFS, не дБ SPL.
- Энергия — FS²·отсчёт.
- PSD — FS²/Гц, односторонняя.
- Спектрограмма — средняя PSD полосы 1/12 октавы: мощность полосы, делённая на ширину, FS²/Гц; цвет — dBFS/Гц.

## Как получить показатели из снимка

- Уровень окна T с (Z) для столбца n: `Σz / Σpcm` по столбцам n−T+1…n. Окно полное, если `Σpcm = T·fs`. Для A/C — `Σa / Σspec` (или `c`).
- Leq сеанса: Z — `totals.sumSquares / (blocks·4096)`; A/C — `totals.weightedPower`. Значения совпадают с последним столбцом `leqAll` истории (тест).
- Энергия полосы j варианта v за столбцы — сумма `energy`; средняя мощность — деление на `Σspec`. Доли — от суммы полос, как `bandPowers`.
- Спектрограмма: `coarse.energy / coarse.spec` — средняя мощность полосы за столбец 10 с; `fine.power` — за кадр. Средняя PSD = мощность / ширина полосы.

## Проверка и объём

`checkNoiseSession` проверяет:

- `kind` и `version`, согласованность настроек с `timeline` и наличием калибровки;
- возрастание границ полос;
- длины всех массивов (L, M, F, B, E, V, число блоков, 16385 бинов);
- неотрицательные конечные значения в суммах;
- `L = ⌈end / fs⌉` и предел 12 ч.

Повреждённый снимок — ошибка без частичного чтения.

Объём снимка: 600 с при 48 кГц без профиля — 3,2 МиБ (тест). Предел 12 ч: 25,5 / 36,6 МиБ при 44,1 кГц, 26,7 / 38,0 МиБ при 48 кГц (без профиля / с профилем). Расчёт по формулам размеров — в [spec.md](spec.md#производительность-и-память). Хранить сеанс без кольца `fine` (останутся только столбцы 10 с спектрограммы) или без `blocks` (пропадёт история RMS блоков) можно только по отдельному решению.
