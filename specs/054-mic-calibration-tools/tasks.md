## Проверено 22.11.2026 на Windows

Финальный прогон на итоговом коде ветки `054-mic-calibration-tools` (основа `1dcbbe2`) перед коммитом:

| `npm run build` | собрано, precache 23 файла (1471,2 КиБ); файлы `field-check` в precache не входят |
| `npm run e2e` (Chromium, канал Chrome, проект `iphone`) | 126 пройдено |

- Первый финальный прогон Chrome выявил нестабильность UX-003. Подтверждение сохранялось, но флажок на мгновение возвращался в прежнее состояние. Причина: рассылка `BroadcastChannel` о записи запускает в том же документе повторное чтение каталога. Оно отменяло чтение после записи, и отметка сбрасывалась до прихода новых данных. Теперь запись ждёт последнего чтения. Повтор `mic-tools` и `noise` 8 раз: 81/81 (до исправления 5 падений из 24).
- Новые тесты 054: `micApply` (6), `micCatalogTools` (8), `c2FieldCheck` (2), дополнения `format` и `noise-capture`, e2e `mic-tools` (4) и изменённые шаги `noise.spec`.
- Эмуляция WebKit на Windows не равна физическому iPhone. Шаги с виртуальным аудиовходом (живой «Анализатор», привязка входа UX-003) проверены в Chromium. В Windows WebKit нет `createMediaStreamDestination`, поэтому там эти шаги завершаются ранним выходом.
- Физически на iPhone реализация 054 пока не проверялась.
