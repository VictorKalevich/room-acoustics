# Текущее состояние приложения

Сверка: 2026-11-10; дополнения дизайн-системы, конструктора комнаты, скана, ручной настройки и порядка работы — 2026-11-11. Здесь описано реализованное поведение; предложения — в
[отдельном списке](deferred.md). История требований — в [решениях](decisions.md).

## Интерфейс и архитектура

Веб-приложение ориентировано на Safari/iPhone, работает локально и поддерживает PWA.
С этапа 022 работа идёт по порядку: сначала комната (один экран «С чего начать», без нижней панели),
затем места колонок. После создания комнаты нижняя панель: **Комната → Расстановка → Анализ → Настройка →
Голос**. Экраны, зависящие от мест колонок, сабвуфера и слушателя (обзор и 3D в «Анализе», «Настройка»,
свип и сравнение замеров, разделы отчёта о колонках), закрыты, пока места не выбраны (подбором, вручную или
«Колонки стоят так»); моды, место для записи, хлопок и анализатор работают по комнате. Скан проходит те же
шаги, что и ручной ввод, и создаёт комнату по «Сохранить»; неуверенный скан сначала открывает поправку
границ. На обзоре — «Что учтено в расчётах», «Что дальше» и «Изменить комнату».
«Комната» — обзор (план, сводка, скан, RT60) и конструктор
с шагами «Размеры», «Стены» (развёртка, окна/двери/проёмы, материал, ковры и шторы),
«Пол и потолок» (ковры, скос), «Мебель» (предметы по типам, обстановка) — этап 019.
Скан применяется сразу после выбора файла; карточка «С чего начать» и выбор файла скрыты, пока
есть скан (до «Очистить»). Исходный скан виден только в «Поправить границы комнаты» — этап 020.
Пока комната не создана (ни скана, ни сохранённой ручной настройки), на «Комнате» только «С чего
начать», а экраны с расчётами предлагают сначала создать комнату. Ручная настройка идёт по шагам
через «Далее» до «Сохранить»; правки конструктора попадают в расчёты по «Сохранить», уход с
несохранёнными правками спрашивает; объекты за стенами перед сохранением показываются списком — этап 021.
Меню открывает измерения, отчёт, импорт/экспорт и справку (до создания комнаты — только импорт/экспорт
и справку). «Проекты» (верхняя панель) возвращают назад кнопкой «← Назад» и повторным нажатием; «Сохранить»
и «Экспорт» — только у созданной комнаты; «Новый проект», «Открыть» из списка и «Импорт» предупреждают, если
введённое пропадёт — этап 023. «Место для записи» подбирает позицию, а не записывает аудио.

Анализ содержит обзор, моды и поле 3D; расстановка — общий блок системы/цели и режимы
авто/вручную; настройка — сабвуфер, EQ и обработку. Измерения объединяют свип,
хлопок, анализатор, сравнение и REW. Старые адреса мод, поля и ручного режима работают.

App связывает экраны с useProject; navigation отвечает за адреса и переходы.
Общие SectionNav, RetainedSection, CalculationStatus и ActionMenu используются повторно.
Это рефакторинг интерфейса и части управления состоянием, не полная переработка ядра.

Этап 018 выделяет дизайн-систему в src/ui/design-system: токены, канонические стили,
публичные примитивы, реестр и каталог. Все CSS-стили приложения используют этот вход;
типографика и интервалы заданы токенами. Старые пути общих компонентов — совместимые
переэкспорты. Правила дальнейшего UI — в [дизайн-системе](../docs/design-system.md).
Выполнена небольшая унификация близких стилей, а не переработка экранов.

## Где хранится состояние

| Данные | Область и поведение |
| --- | --- |
| Комната, система, ограничения, расстановка, замеры | Общий Project; одна настройка продолжает влиять на все связанные инструменты |
| Мебель, ковры, шторы, режим «мебель списком» | В комнате проекта (зоны с типом, coverings, furnitureList); формат файла прежний, поля необязательные |
| Найденное в скане | Пометка fromScan у проёмов, окон, дверей, коридоров и мебели; scanInfo.rotation — поворот после скана |
| Сетка скана, распознавание, применённый выбор | IndexedDB, хранилище scans по проекту; не входит в файл проекта и синхронизацию; удаляется «Очистить» |
| Комната создана | Поле проекта roomReady; у проектов до 021 выводится при открытии (нетронутый проект — нет) |
| Черновик конструктора | localStorage ra-room-draft-<проект>: комната, достигнутый шаг, введённые размеры и что меняли (для пометки «по умолчанию»); не входит в файл проекта; удаляется «Сохранить», «Не сохранять», «Сбросить черновик», сканом и «Очистить» |
| Места выбраны | Поле текущей расстановки placed; пока нет — места по умолчанию для текущей комнаты; у проектов до 022 выводится при открытии |
| Подстройка по замеру | room.calibration: множитель, название замера, герметичность до подстройки (её возвращает «Сбросить подстройку») |
| Подразделы и прокрутка | Запоминаются в текущем сеансе |
| Локальные результаты инструментов | Сохраняются при переходах; зависимые результаты сбрасываются при изменении входов; другой проект сбрасывает локальное состояние |
| Сглаживание | Три независимых настройки localStorage: voice, placement-auto, placement-manual; не поля проекта |
| Цель карты голоса | localStorage ra-voice-map-goal; не меняет цель расстановки колонок |
| Высота микрофона | Существующая высота mouthZ в проекте; posture оставлено для совместимости |

Скрытый экран измерений останавливает микрофон; позднее разрешение не запускает скрытую
запись. Прослушивание EQ останавливается при уходе. Общий мини-плеер сохраняет своё
поведение. Обработка учитывается при включении; её редактор остаётся доступен.

## Графики и показатели

- Расстановка: без дополнительного сглаживания, 1/12, 1/6, 1/3, 1/2; по умолчанию 1/12.
- Голос: исходная кривая 1/6, затем 1/3 и 1/2; по умолчанию исходная.
- Психоакустический режим отдельный: 1/3 внизу с переходом к 1/6; это приближение для
  просмотра тонального баланса, а не постоянная 1/3 и не модель всего слухового восприятия.
- Сглаживание меняет только рисунок; исходные данные, оценки, карты и подбор сохраняются.
- Голос: отдельно неровность спектра, вклад комнаты roomDb и RT60. Цели карты —
  «Ровнее спектр» (исходная, по умолчанию) и «Меньше комнаты».
- Зелёная область карты означает относительное преимущество по выбранной цели,
  а не отсутствие отражений, эха или гарантию хорошей записи.
- «Карта звука» на «Расстановке» (оба режима) прячет только окраску плана и её шкалу;
  выбор «Карта для»/«Что ищем», пояснения и «Слой карты» остаются видимыми (D11, 2026-11-11).

## Границы расчётов

Подбор колонок ориентирован на низкочастотную часть: верхняя граница основной оценки
ограничивается частотой Шрёдера в пределах 120–300 Гц. Нижняя связана с диапазоном
источников и ограничена снизу 20 Гц; слишком узкий диапазон корректируется.
В волновом предварительном поиске используется более узкая полоса; финальная оценка
пересчитывается. Наличие более высоких мод в модели не означает оптимизацию по всем
слышимым частотам. Расширенный график до 20 кГц не реализован.

Сетка расстановки (12 или 24 отсчёта на октаву в зависимости от этапа/цели) не равна
сглаживанию 1/12 или 1/24. Голос использует энергию полос 1/6 октавы, по умолчанию
80–12 000 Гц, с 16 направлениями. Более подробного исходного вокального спектра нет.
Сравнивать точность этих двух моделей одним числом нельзя.

«Без комнаты» на графике расстановки — номинальный отклик источников и фильтров
с когерентным суммированием, без геометрического ослабления и направленности. Это не
замер колонок в безэховой камере. Две колонки могут дать около +6 дБ относительно
одного источника в своей полосе. «Базовая» — исходная расстановка алгоритма с учётом
ограничений, а не обязательно предыдущая реальная расстановка пользователя.

Мебель из скана задаёт запрещённые зоны и получает тип по категории; общая обстановка участвует
в поглощении. При «мебели списком» на 500–4000 Гц вместо общей оценки считаются остаток
0,15 м²/м² пола, мягкая мебель, кровати, стеллажи с книгами, ковры и шторы (обобщённые табличные
значения, порядка ±30–40 %); 63–125 Гц — общая оценка, 250 Гц — переход. Это меняет RT60,
частоту Шрёдера и зависящие от них величины, но не затухание мод на 63–125 Гц.
Жёсткая мебель (шкафы, столы, стулья, пустые стеллажи) в расчёт звука не входит.
В модели голоса мебель упрощённо влияет на отражение от пола, без полноценной геометрии
вертикальных поверхностей. Скан LiDAR даёт геометрию, но не измеряет поглощение материалов.
Эти ограничения не исправлялись в рамках UI.

## Подтверждение и ограничения проверки

Подробные критерии и пути к тестам — в спецификациях 014–018. До дизайн-системы последний зафиксированный
в ходе реализации браузерный прогон: **94 успешных, 2 пропущенных**; lint и сборка
успешны. Последний зафиксированный unit-прогон — **269 тестов**. Это исторические
результаты, а не новый прогон при обновлении документации.

В этапе 018 заново прошли 269 unit-тестов, lint и сборка; 94 существующих e2e прошли,
2 аудиосценария пропущены, 6 новых проверок дизайн-системы прошли отдельным итоговым
прогоном. Подробности и проверка каталога — в [018](018-design-system/spec.md).

В этапе 023 (2026-11-12, та же среда): 307 unit-тестов (без изменений — расчёты не менялись), lint с `design:check`
и сборка прошли; 72 сценария e2e проекта `iphone` прошли, включая 5 новых для экрана «Проекты» (без комнаты,
начатая настройка, созданная комната до и после сохранения, «Открыть» из списка, «Импорт»). WebKit и физический iPhone не проверялись.

В этапе 022 (2026-11-11, та же среда): 307 unit-тестов (4 новых — признак «места выбраны», вывод для старых
проектов, подстройка по замеру, выбор мест изменением), lint с `design:check` и сборка прошли; 67 сценариев
e2e проекта `iphone` прошли, включая 4 новых (скан по шагам с поправкой границ, неуверенный скан, закрытые экраны
без выбранных мест, исправленный первый подбор в своей комнате) и обновлённые сценарии первого запуска и скана.
WebKit и физический iPhone не проверялись.

В этапе 021 (2026-11-11, та же среда): 303 unit-теста (9 новых — вписывание объектов в стены, признак
«комната создана», черновик), lint с `design:check` и сборка прошли; 63 сценария e2e проекта `iphone`
прошли, включая 4 новых (первый запуск, ручная настройка, уход с правками, уменьшение комнаты).
Сценарии начинают с комнаты, созданной ручной настройкой; первый запуск и скан — с нового проекта.
WebKit и физический iPhone не проверялись.

В этапе 020 (2026-11-11, та же среда): 294 unit-теста (7 новых — применение и хранение скана),
lint и сборка прошли; 60 сценариев e2e проекта `iphone` прошли, включая 4 новых сценария скана и
2 обновлённых. WebKit не запускался.

В этапе 019 (2026-11-11, контейнер Linux, эмуляция iPhone в Chromium): 287 unit-тестов,
lint с `design:check` и сборка прошли; 56 сценариев e2e проекта `iphone` прошли, включая
5 новых сценариев конструктора и обновлённые сценарии экрана «Комната». WebKit в этом
прогоне не запускался.

Два аудиосценария пропускались в Windows WebKit без AudioContext. Проверка на физическом
iPhone и реальный акустический замер не подтверждены. Открытые расчётные задачи не
закрыты: см. [отложенное и открытое](deferred.md).
В текущем workflow WebKit выполняется с continue-on-error; успешный общий CI сам
по себе не подтверждает прохождение WebKit. Это существующее ограничение, не исправление
в рамках сверки документации.
