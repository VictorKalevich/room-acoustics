# 040 — Совет про внешние файлы glTF — только когда они есть

Статус: реализовано 2026-11-16. Основание: [D35](../decisions.md).
Сообщение «glTF ссылается на внешние файлы. Экспортируйте скан в GLB (один файл).» получает только скан, геометрия
которого лежит во внешнем файле; повреждённый glTF/GLB получает «Не удалось прочитать glTF/GLB: файл повреждён.».

## Задача владельца

2026-11-16, после 039: исправить ошибку из [отложенного](../deferred.md) — испорченный glTF/GLB получает совет про
внешние файлы. Предложенный способ, на который владелец ответил «да»: не искать слово «load» в тексте ошибки, а до
разбора проверить, есть ли в файле ссылки на внешние файлы; добавить тесты.

## Поведение до

Совет выбирался по тексту ошибки загрузчика three.js: `load|fetch|uri`. «Load» есть в префиксе «THREE.GLTFLoader:»
почти любой его ошибки.

| Файл | Было |
| --- | --- |
| GLB версии 1, `.gltf` без раздела `asset` (проверено запуском `loadScan`) | совет про внешние файлы вместо «файл повреждён» |
| `.gltf` или GLB с геометрией во внешнем `.bin` | загрузчик запрашивал файл с этим именем у сайта приложения. В браузере после отказа — совет (по коду загрузчика, не запускалось); в node — «файл повреждён» (проверено) |
| `.gltf` с внешней картинкой-текстурой, геометрия внутри | читается: недоступная текстура пропускается |

## Требования

- FR-4001: если у буфера glTF/GLB есть `uri` и это не `data:`, загрузка отклоняется с «glTF ссылается на внешние файлы.
  Экспортируйте скан в GLB (один файл).» ещё до чтения геометрии; внешний файл не запрашивается.
- FR-4002: любая другая ошибка разбора glTF/GLB — «Не удалось прочитать glTF/GLB: файл повреждён.».
- FR-4003: исправные файлы читаются, как прежде: GLB с двоичным блоком, GLB и `.gltf` с буфером `data:`, `.gltf` с
  внешней текстурой (геометрия внутри).

## Границы

- Меняется только ветка glTF/GLB в `src/scan/load.ts`: проверка буферов — дополнение `beforeRoot` к загрузчику
  three.js, которое срабатывает после разбора JSON и до загрузки буферов. Остальные форматы и общая часть загрузки
  не меняются.
- Внешние картинки не проверяются: для распознавания комнаты нужна только геометрия.

## Приёмка

1. Тесты FR-4001–FR-4003 в `tests/scan/badfiles.test.ts`. Без исправления тесты на внешний буфер и на повреждённые
   файлы падают, тест исправных проходит.
2. `npm test`, `npm run lint`, `npm run build`, `npm run e2e` проходят.
3. Пункт отложенного о совете про внешние файлы закрыт.

## Реализация и проверка

2026-11-16:

- `src/scan/load.ts`: дополнение загрузчика `room_acoustics_external_buffers` в `beforeRoot` смотрит `buffers[].uri`.
  Есть внешний — загрузка прерывается до запроса буферов, ошибка — совет про GLB. Иначе любая ошибка — «файл
  повреждён». Проверка текста ошибки на `load|fetch|uri` убрана.
- `tests/fixtures/synthetic.ts`: `dataUri`, `gltfJson` (glTF 2.0, одна сетка, `uri` буфера на выбор), `toGLB` (блоки
  JSON и BIN, версия контейнера).
- `tests/scan/badfiles.test.ts`:
  - четыре исправных варианта дают все 7 754 треугольника и комнату 5 × 4 × 2,6 м;
  - внешний `.bin` у `.gltf`, второй внешний буфер рядом с встроенным и внешний буфер у GLB дают совет про GLB;
  - GLB версии 1, `.gltf` без `asset` и GLB, обрезанный наполовину, дают «файл повреждён».
  В node у загрузчика нет `ProgressEvent` и `self`, поэтому тесты подставляют их на время своего блока.
- Без исправления в `src/scan/load.ts` тесты на внешний буфер и на повреждённые файлы падают, тест исправных
  проходит.
- `npm test`: 510 тестов в 59 файлах. `npm run lint` и `npm run build` — без ошибок. `npm run e2e`: 96 сценариев
  и подготовка комнаты проходят в эмуляции iPhone в Chrome. В сценариях сканы только OBJ и STL, glTF/GLB в e2e не
  загружается. WebKit и физический iPhone не проверялись.

## Замечено, не исправлено
