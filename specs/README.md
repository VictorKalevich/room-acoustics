## Как читать и поддерживать

Ранние spec/plan/research отражают решения своего этапа. Для текущего интерфейса
приоритетны явно указанные поздние изменения; это не отменяет остальных контрактов
ядра и формата проекта. Незакрытые задачи сохраняют статус.

При каждой завершённой фиче обновлять требования, критерии приёмки, задачи и этот индекс,
а также журнал решений при изменении прежних договорённостей. Для новой самостоятельной
фичи создавать следующий свободный номер; для уточнения существующей — обновлять её
спецификацию. План и исследование нужны по сложности задачи, а не ради копирования шаблона.

Любое изменение UI начинается с дизайн-системы. Новые компоненты, текстовые стили
и отступы добавляются в систему и документацию вместе с фичей. Существующий дизайн
не меняется вне объёма задачи; почти одинаковые варианты не дублируются.
