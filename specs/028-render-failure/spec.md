# 028 — Сбой отрисовки не выводит приложение из строя

Статус: реализовано 2026-11-14. Основание: [D21](../decisions.md), шаг 1
[плана рефакторинга](../../docs/refactoring-roadmap.md) ([описание шага](../../docs/refactoring/step-1-render-failure.md)).
Уточняет открытие проекта ([001](../001-room-acoustics-mvp/spec.md), [026](../026-calc-precision/spec.md) —
«проект с частично неверными данными открывается»). Формат и версия файла проекта, расчёты и видимое поведение
при исправных данных не меняются.

## Задача владельца

Команда владельца на шаг 1 плана: одно исключение при отрисовке любого экрана не должно оставлять пользователя
без приложения. Убрать известную причину такого сбоя (неверный `result` в сохранённом проекте) и сам класс
последствий (границы ошибок). Тексты и состав действий сообщений — из описания шага; владелец согласовал их
отправкой команды.

## Что было (сверено с кодом 2026-11-14, коммит `575e574`)

- В `src` нет границ ошибок. «Комната» смонтирована всегда, «Расстановка» — с создания комнаты; обе только
  скрываются. «Настройка» и «Измерения» остаются смонтированными после первого посещения (`RetainedSection`).
  Исключение в скрытом экране ломает и видимый.
- `normalizeProject` пропускает `result` как есть (`raw.result ?? null`), у `scanInfo` проверяет только `applied`.
- Воспроизведение: до загрузки страницы `localStorage['ra-draft-pending'] =
  {"id":"poison","name":"Проверка","room":{},"roomReady":true,"result":{"best":"x","baseline":5}}` → ошибка
  `Cannot read properties of undefined (reading 'filter')`, нет `main.content` и `.tabbar`, видна только шапка;
  после перезагрузки и на `#projects` — то же. Выход — только стереть данные сайта со всеми проектами.

## Требования

### А. Проверка формы сохранённых данных при открытии

- FR-2801: `result` неверной формы отбрасывается: `null`, выбранный вариант — первый (`selectedIndex = 0`).
  Пользователь теряет только результат подбора; «Расстановка» предлагает подобрать заново. Отбрасывается только
  то, что текущий код не может показать или посчитать:
  - результат — объект; `best` — список вариантов, `baseline` — вариант, `notes` — список; `fLo`, `fHi`,
    `evaluated`, `elapsedMs` — числа или `null` (NaN и ±∞ в JSON записываются как `null`);
  - вариант — объект; `listener` и `sources[].pos` — точки с конечными координатами, `sources[].id` — строка;
    `score`, `scoreCenter`, `scoreSeats` — числа или `null`; `penalties` — список объектов; `response.f`,
    `response.db`, `response.target` — списки чисел (или `null`);
  - необязательные поля прежних версий могут отсутствовать: `seats` (появилось в 002), `objScore`, `robust`,
    `subSettings`, `scheme`, `notes`, `angleDeg`, `stale`. Если поле есть — оно своего типа; `subSettings` — как
    у расстановки (FR-2802). Пометка «устарел» (`stale`) читается как да/нет и не проверяется.
- FR-2802: остальные поля, которые `normalizeProject` возвращал без проверки формы, проверяются по таблице ниже.
  Неверный элемент списка убирается, неверное необязательное поле убирается (читатели подставляют умолчание),
  неверное обязательное значение заменяется умолчанием.
- FR-2803: проверяется только форма (тип, значение из перечня), а не смысл величин (диапазоны расчётных
  величин — вне шага). Верные данные не меняются: настоящий результат подбора и проекты из тестов проходят
  нормализацию без изменений.
- FR-2804: формат и версия файла проекта прежние; сохранённые проекты, файлы и адреса открываются как раньше.

| Поле | Кто читает | Было | Проверка (028) |
| --- | --- | --- | --- |
| `result` | «Расстановка»: вкладки вариантов, оценка, план, карта звука, график, таблица мест; пометка «устарел» при правке; «Мастер» | без проверки | FR-2801; иначе `null` |
| `selectedIndex` | «Расстановка»: выбранный вариант | число | целое ≥ 0, иначе 0; 0 — и когда `result` отброшен |
| `scanInfo` (не объект) | все проверки «есть скан» | `null` | без изменений |
| `scanInfo.fileName` | сводка скана, «Что учтено», вступление шагов, загрузка поправки границ | без проверки | строка, иначе пустая строка |
| `scanInfo.confidence` | предупреждение «скан распознан неуверенно» | без проверки | конечное число, иначе поле убирается (предупреждения нет, как без поля) |
| `scanInfo.rotation` | «Колонки у другой стены», «Поправить границы комнаты» (поворот в систему скана) | без проверки | целое число, иначе убирается (читается как 0) |
| `scanInfo.applied` | поправка границ | проверялось (026) | без изменений |
| прочие поля `scanInfo` (размеры, единицы, покрытие стен, предупреждения…) | приложением не читаются, только хранятся | без проверки | не нужна |
| `current.id`, `setups[].id` | ключи списков, выбор варианта | без проверки | строка, иначе новый id |
| `current.name`, `setups[].name` | списки вариантов, сравнение, отчёт | без проверки | строка, иначе имя по умолчанию («Текущая», «Вариант») |
| `current/setups[].subSettings[…]` | «Настройка» (сабвуфер, экспорт фильтров), отчёт, отклик и карты, 3D, CamillaDSP | только «объект» | `delayMs`, `phaseDeg`, `gainDb` — конечные числа, иначе запись сабвуфера убирается (читается как 0 / 0° / 0 дБ); `peq` — список `{f, gainDb, q}`, `allpass` — список `{f, q}` из чисел, иначе список убирается |
| `current/setups[].crossoverHz` | отклик (фильтр раздела), «Настройка» | `?? null` | конечное число или `null` |
| `constraints.crossover.adjustable`, `min`, `max` | подбор частоты раздела (перебор от `min` до `max`), «Система», «Настройка» | без проверки (`spkLimit`, `subLimit` — проверялись) | да/нет и конечные числа, иначе умолчания |
| `constraints.dba` | подбор, флажок DBA | без проверки | не нужна: читается как да/нет |
| сабвуфер: `delayMode`, `phaseMode`, `maxDelayMs`, `peqBands` | перебор настроек сабвуфера, подбор своих фильтров, «Система», «Настройка» | без проверки | значение из перечня / конечное число, иначе умолчание сабвуфера (`peqBands` — убирается) |
| сабвуфер: `levelAdjustable`, `allpass` | то же | без проверки | не нужна: читаются как да/нет |
| `room.openings[]` | план, развёртка стены, отчёт, затухание, волновая модель | только «объект» | стена из четырёх, `a0`, `a1`, `height` — конечные числа; иначе проём убирается |
| `room.extensions[]` | план, отчёт, расчёт, волновая модель | объект и проверка коридора (сравнения пропускали строки; без `arch` проект не открывался) | стена из четырёх, `a0`, `a1`, `depth`, `height` и `arch.a0/a1/height` — конечные числа; иначе коридор убирается |
| `room.treatments[]`: `thickness`, `width`, `height` | отчёт, план, расчёт обработки | вид и «> 0» (строки проходили) | конечные числа > 0, иначе элемент убирается |
| `room.treatments[]`: `corner`, `wall`, `at`, `z`, `x`, `y`, `gap` | отчёт (`corners[…].toLowerCase()`), план, расчёт (`corner.split`) | без проверки | значение из перечня / конечное число, иначе поле убирается (читается умолчание) |
| `room.zones[].kind`, `name` | подписи плана и списков, расчёт | только «объект» (координаты вписываются в комнату) | вид из четырёх, иначе «Другое»; подпись не строка — убирается |
| `room.calibration.dampingScale`, `source` | затухание мод, «Что учтено», отчёт | `> 0` (строки проходили) | множитель — конечное число > 0, иначе подстройка сбрасывается; источник не строка — убирается |
| `room.slope.low`, `run` | геометрия, поиск мест, план | `> 0` (строки проходили) | конечные числа, иначе скоса нет |
| `room.source`, `zones[].canSit`, `zones[].id` | сравнения, ключи | без проверки | не нужна |

Уже проверялось и не менялось: `id`, `name`, `updatedAt`, размеры и температура комнаты, материалы, обстановка,
герметичность, ковры и шторы, окна и двери, координаты зон (вписываются), источники (вид, диапазон, высота),
ограничения (числа, зона сабвуфера, места, пределы техники, цель), места и слушатель, замер и история, голос,
точность, «комната создана».

### Б. Границы ошибок

- FR-2805: каждый раздел в `main.content` находится в своей границе ошибок: «Комната», конструктор комнаты,
  «Анализ», «Расстановка», «Настройка», «Проекты», «Измерения», «Голос», «Отчёт», «Справка», «О приложении».
  Исключение при отрисовке одного раздела не затрагивает остальные разделы, шапку, меню и нижнюю панель;
  на месте упавшего раздела — сообщение.
- FR-2806: граница стоит внутри скрытой обёртки раздела: упавший скрытый раздел ничего не показывает, пока на
  него не перейдут. Раздел, который монтируется только при открытии, при повторном открытии пробует отрисоваться
  заново; постоянно смонтированный — по «Попробовать снова».
- FR-2807: над всем приложением — граница оболочки: сбой шапки, меню, полосок над разделами или самого `App`
  даёт сообщение, а не пустую страницу.
- FR-2808: ошибка, пойманная границей, записывается в журнал на устройстве (`errlog`) с названием раздела
  («экран «Расстановка»») или «оболочка приложения».
- FR-2809: граница ловит исключения при отрисовке, в эффектах, `ref` и при размонтировании — Preact 11.2.0
  направляет их в ближайшую границу (сверено по исходникам: `diff`, `commitRoot`, `applyRef`, `unmount`,
  `hooks: flushAfterPaintEffects`). Ошибки в обработчиках событий, таймерах и промисах идут мимо границы и,
  как раньше, записываются общим журналом (`installErrorLog`).
- FR-2810: сообщения:

  | Где | Заголовок и текст | Действия |
  | --- | --- | --- |
  | Упал один раздел | «Раздел не открылся». «Ошибка записана в журнал. Проект не удалён.» | «Попробовать снова», «Экспортировать проект», «Сообщить о проблеме» |
  | Упала оболочка | «Приложение не открылось». Тот же текст. | «Перезагрузить», «Экспортировать проект», «Начать новый проект» (с подтверждением) |

- FR-2811: «Попробовать снова» отрисовывает раздел заново; если причина осталась — снова сообщение.
  «Сообщить о проблеме» открывает «О приложении» с существующим блоком «Сообщить о проблеме»; на самом
  «О приложении» этого действия нет.
- FR-2812: «Экспортировать проект» — тот же экспорт, что в «Проектах» (общая функция: «Поделиться» на iPhone,
  скачивание на компьютере, время последнего экспорта), с тем же правилом: доступен, когда комната создана (D16).
  В сообщении раздела экспортируется текущий проект, в сообщении оболочки — рабочий проект с устройства.
- FR-2813: «Начать новый проект» в сообщении оболочки спрашивает подтверждение («Отмена» / «Начать новый
  проект»): рабочий проект на устройстве заменяется новым, сохранённые в «Проектах» остаются; затем приложение
  перезагружается на «Комнате». «Перезагрузить» перезагружает страницу.
- FR-2814: сообщение — новый элемент дизайн-системы **FailurePanel** (по образцу закрытых экранов: `Panel`,
  пояснение `.small`, `.btn-row`); тексты — в `strings.ts`. Он внесён в реестр, каталог и
  `docs/design-system.md`. Новых стилей, текстовых ролей и отступов не требуется.

## Приёмка

1. Проект с `result` неверной формы (воспроизведение выше) открывается: видны содержимое и нижняя панель,
   «Расстановка» предлагает подбор заново, ошибок страницы нет.
2. Результат настоящего подбора после сохранения и открытия совпадает с исходным.
3. При исключении в отрисовке одного раздела остальные разделы и меню работают, на его месте — сообщение;
   «Попробовать снова» возвращает раздел, если причина устранена; «Экспортировать проект» выдаёт файл, который
   затем открывается импортом.
4. Сообщение проходит `npm run design:check`, есть в реестре, каталоге и документации дизайн-системы, не даёт
   горизонтальной прокрутки на 320 и 393 px, светлая и тёмная темы.
5. Сбой оболочки даёт сообщение «Приложение не открылось», а не пустую страницу; «Перезагрузить»,
   «Экспортировать проект» и «Начать новый проект» с подтверждением работают.
