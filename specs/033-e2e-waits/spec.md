# 033 — Сквозные сценарии без фиксированных ожиданий

Статус: в работе с 2026-11-16 (ветка `refactor/step-6`). Основание: [D27](../decisions.md), шаг 6
[плана рефакторинга](../../docs/refactoring-roadmap.md) ([описание шага](../../docs/refactoring/step-6-e2e-waits.md)).
Сквозные сценарии ждут событий, а не времени: запись на устройство — по содержимому хранилища, фокус — перед вводом,
прочее — по состоянию страницы. Меняются только `tests/e2e`; приложение, его поведение и конфигурация Playwright
не меняются.

## Задача владельца

Команда владельца на шаг 6 плана. Интерфейс покрыт только сквозными сценариями, а шаги 7–9 перестраивают его; сценарий,
который иногда падает сам по себе, приучает не верить красному результату. Нужно убрать фиксированные паузы и гонку
фокуса в подготовительном сценарии.

Гонка фокуса: «Настроить комнату вручную» (`src/ui/screens/RoomScreen.tsx`) после перехода ставит фокус в `#room-depth`
через два `requestAnimationFrame`. `fill` в Playwright ставит фокус в поле и отдельной командой вставляет текст; если
кадр приходит между ними, текст попадает в «Глубину». Сценарии, которые нажимают кнопку и сразу вводят размеры:
`room.setup.ts`, `projects.spec.ts` (два места), `start-menu.spec.ts` (одно). `room-first.spec.ts` после нажатия уже
проверяет фокус в «Глубине» (`toBeFocused`) и только потом вводит. Ещё два нажатия (`room-first.spec.ts`,
`start-menu.spec.ts`) продолжают настройку с шага «Стены» — там приложение фокус не ставит. Других мест, где приложение
ставит фокус через кадры, в `src` нет.

Наблюдения 2026-11-16 на этой машине до изменений: первый обычный прогон `npm run e2e` остановился на `room.setup.ts`
(в снимке страницы «2,5» — в «Глубине» с фокусом, «Высота» пуста, «Далее» закрыта), второй — 90 сценариев. Временная
шкала событий подготовки: два кадра после нажатия приходят примерно через 30 мс, ввод трёх размеров занимает около
10 мс, окно гонки — 1–2 мс между фокусом поля и вводом.

## Требования

- FR-3301: ожидание записи рабочего проекта на устройство — по содержимому хранилища. Общая функция в
  `tests/e2e/helpers.ts` читает черновик (`meta/draft`) и список проектов с сохранённым сканом (`scans`) и ждёт
  (`expect.poll`), пока черновик не станет таким, как нужно сценарию. Чтение не создаёт базу, если её ещё нет, и
  закрывает своё соединение.
- FR-3302: ожидание черновика конструктора (021) — по `ra-room-draft-<проект>` в `localStorage`; журнала ошибок — по
  `ra-errors` (общая функция `errlog`).
- FR-3303: все места, где сценарий нажимает «Настроить комнату вручную» и сразу вводит размеры, через общую функцию
  нажимают кнопку и дожидаются фокуса в «Глубине».
- FR-3304: фиксированных пауз нет, кроме случаев, когда события для ожидания нет без изменения приложения; у каждой
  оставшейся — комментарий с причиной.
- FR-3305: проверки сценариев прежние; ожидание заменяется условием, ни одна проверка не убрана и не ослаблена. Число
  сценариев не уменьшается, пропущенных нет.
- FR-3306: без изменений — `src`, поведение приложения, `playwright.config.ts`, сценарии вне перечисленных мест.

## Приёмка

1. В `tests/e2e` нет `waitForTimeout`, либо у каждого оставшегося есть комментарий с причиной.
2. Набор проходит три раза подряд при обычном запуске и один раз при запуске с отложенной отрисовкой кадров.
3. Число сценариев не меньше базового (90 на 2026-11-16), ни один не помечен пропущенным.
4. В `src` нет изменений.
5. Изменённые файлы сценариев проходят `npx playwright test --project=iphone --repeat-each=3`.
6. Гонка фокуса воспроизводится детерминированно на прежних сценариях и не воспроизводится на новых.
