## 2. Существующая реализация (инвентаризация)

Проверено по коду на `aa3b123`: аналитические комнатные моды; затухающие модальные модели; комплексные передаточные функции; низкочастотный FDTD; двумерные и трёхмерные поля; оптимизация источников и слушателей; несколько сабвуферов и DBA; Сэбин и Эйринг; открытые проёмы и смежные пространства; герметичность; первые отражения; подбор места записи голоса; упрощённые поглощающие конструкции; автоматический EQ; FIR минимальной и линейной фазы; согласование сабвуферов; экспорт DSP; FFT; свипы; хлопок; RTA; шумомер; калибровки микрофонов; история шумомера; импорт геометрических сканов; защита черновиков и несохранённых данных.

Ключевые исходники (все существуют): `src/core/modes.ts`, `fdtd.ts`, `response.ts`, `placement.ts`, `system.ts`, `reverb.ts`, `filters.ts`, `dsp.ts`, `eq.ts`, `subfilters.ts`, `voice.ts`, `treatments.ts`, `overview.ts`, `camilla.ts`; `src/state/project.ts`, `storage.ts`, `variant.ts`; `src/ui/App.tsx`; `src/ui/screens/MeasureScreen.tsx`.

Ядро не переписывается без необходимости. Сохраняются полезные технические компоненты планов, графиков, трёхмерных полей, калибровки, обмена с воркерами и обработки ошибок.

## 4. Изоляция v2

**Git.** Разработка — в ветке `redesign/v2` от `aa3b123`. `main` в рамках v2 не меняется, merge и push — только по разрешению владельца. **[реализовано V2-001]**

**Запуск и сборка.** **[реализовано V2-005]**

| | legacy | v2 |
| --- | --- | --- |
| Конфигурация | `vite.config.ts` | `vite.v2.config.ts` |
| Точка входа | `index.html` → `src/main.tsx` | `src/v2/app/index.html` → `main.tsx` |
| Dev | `npm run dev`, порт 5173 (по умолчанию Vite) | `npm run dev:v2`, порт 5174, `strictPort` |
| Сборка | `npm run build` → `dist/` | `npm run build:v2` → `dist-v2/` |
| Preview | `npm run preview`, 4173 (e2e) | `npm run preview:v2`, 4174, `strictPort` |
| PWA | `vite-plugin-pwa`, `sw.js`, манифест | нет: ни плагина, ни service worker, ни манифеста |
| `public/` | иконки и `field-check/` | не копируется (`publicDir: false`) |
| Стили | `src/styles.css` (Golos Text) | `src/v2/app/styles.css` (Acoustic Lab) |
| e2e | `playwright.config.ts`, `tests/e2e` | `playwright.v2.config.ts`, `tests/v2/e2e` |

Разные порты — разные origin: IndexedDB, LocalStorage, Cache Storage и service worker legacy не разделяются с dev-оболочкой v2.

**Хранилище при будущей публикации.** Отдельный URL-путь сам по себе не изолирует хранилище: на одном origin общие IndexedDB, LocalStorage и Cache Storage. Service worker legacy зарегистрирован со scope `./` (`/room-acoustics/`) и обслуживает навигацию внутри scope, поэтому страница `/room-acoustics/v2/` на том же origin попала бы под его управление. Для тестовой публикации v2 предпочтителен отдельный origin; при одном origin нужно заранее решить scope service worker, имена Cache Storage и IndexedDB, `id` манифеста и правила обновления. В первом пакете тестовой публикации нет.

**Публикация по D60 (28.11.2026).** Владелец выбрал один origin: v2 лежит рядом с legacy по `/room-acoustics/v2/`. Что решено:

- область service worker: legacy исключает `v2/**` из precache и `/v2/` из навигационного запасного ответа;
- Cache Storage v2 не использует;
- у IndexedDB и ключей разные имена (D60);
- манифеста у v2 нет, и `id` не нужен.

При замене legacy на v2 и PWA для v2 решения пересматриваются (R58, R61).

## 5. Адаптеры вычислений

Поток: `RoomConfiguration v2 → валидация → адаптер → существующее ядро → CalculationResult`.

Адаптер (V2-007):

- преобразует координаты по утверждённой системе координат v2 ([data-model.md](data-model.md#система-координат));
- проверяет единицы и применимость физической модели;
- сохраняет численное поведение прежних расчётов при эквивалентных входных данных (проверяется тестами эквивалентности);
- возвращает предупреждения и не отбрасывает неподдерживаемые параметры молча;
- для неподдерживаемой геометрии или свойства обозначает приближение или недоступность расчёта.

Используются существующие контракты ядра (`Room`, `SourceSpec`, `Setup`, `Constraints`).

## 6. Состояние

Разделяются: предметные данные; состояние интерфейса; вычислительные результаты; аудиосессии.

- Единый источник предметных данных. Изменения — через типизированные прикладные операции, например `moveObject`, `updateMaterial`, `addTreatment`, `applyRecommendation`, `createExperiment`, `confirmExperiment` (примеры контрактов, не обязательные имена).
- Операции выполняют валидацию, согласованное сохранение, обновление истории (отмена и повтор) и инвалидирование зависимых расчётов.

## 7. Реактивные вычисления

- Изменение параметра инвалидирует только зависимые результаты. Зависимости определяются физическим методом: перемещение источника не меняет собственные частоты идеализированной прямоугольной комнаты, но меняет наблюдаемый отклик.
- Кэширование; идентификаторы задач; хеш значимых входных данных; версия алгоритма; ревизия конфигурации; прогресс; отмена; контроль актуальности. Устаревшая задача не перезаписывает новый результат.
- Тяжёлые вычисления — в Worker. Обновление при перетаскивании ограничено по частоте. Несколько тяжёлых FDTD-симуляций одновременно по умолчанию не запускаются.
- Переиспользуются типизированный обмен с воркерами (030), `computeTask` (034) и очередь по видимости (035).
- WebAssembly — только после профилирования и подтверждения необходимости.

## 8. Аудиоархитектура

- Единый сервис аудиосессий: получение входа, воспроизведение, остановка, освобождение ресурсов, реакция на смену маршрута и прерывание.
- Используются проверенные механизмы legacy: аудиотракт, каталог калибровок, сохранение несохранённых измерений (D57), диагностика входа (D56).
- Тяжёлая обработка записей отделена от UI. AudioWorklet — для потоковых задач, Worker — для обработки и вычислений.
- Измерительная подсистема не требует создания комнаты.
- Оболочка первого пакета не создаёт `AudioContext`, не запрашивает микрофон и не воспроизводит звук. **[реализовано V2-005, проверяет `tests/v2/e2e/shell.spec.ts`]**

## 12. Публикация и CI

**Реализовано V2-004:**

- `deploy.yml` (production): запуск по-прежнему push в `main` и ручной. Задача `deploy` и шаг `upload-pages-artifact` выполняются только при `github.ref == 'refs/heads/main'`. Права `pages: write` и `id-token: write` — только у `deploy` (у `build` и `e2e-safari` — `contents: read`). Группа очереди для `main` прежняя (`pages`); ручной запуск на другой ветке идёт в свою группу и не отменяет публикацию `main`. Шаги сборки legacy (lint, unit, build, e2e, e2e-safari) не изменены.
- `v2-check.yml`: push и pull request в `redesign/v2`, ручной запуск. Права — только `contents: read`; нет окружений, артефакта Pages и деплоя. Шаги: `npm ci`, lint, unit, сборка legacy, сборка v2, smoke v2, e2e legacy.
- Текст обоих workflow проверяет `tests/v2/workflows.test.ts`.

**Инфраструктура (проверено чтением API 27.11.2026, без изменений):** окружение `github-pages` имеет правило по веткам — разрешена только `main` (`custom_branch_policies: true`, политика `main`). `can_admins_bypass: true`. Настройки Pages (источник публикации) и права Actions без авторизации не читаются — не проверены.

**Не реализовано и не заявляется:** абсолютная защита от любой публикации. Изменения `deploy.yml` действуют только в ветке `redesign/v2`; в `main` остаётся прежний файл без проверки ветки, пока владелец не разрешит перенос. Ручной запуск старого `deploy.yml` на ветке без этой защиты должно остановить правило окружения `github-pages` (публикация только из `main`), но фактическим запуском это не проверялось. При `can_admins_bypass: true` администратор может обойти правила окружения — владельцу проверить, нужно ли это. Другие способы публикации (локальная загрузка, сторонние действия, изменение настроек Pages) workflow не контролирует.

**Публикация v2 (D60):** `npm run build` собирает и v2 в `dist/v2`, поэтому прежний `deploy.yml` публикует её вместе с legacy без изменения workflow. Перед публикацией CI прогоняет unit-тесты v2 и `tests/e2e/v2-pages.spec.ts` в наборе legacy.

## 13. Стратегия тестирования

Существующие тесты сохраняются. Дополняются: core-, domain-, adapter-, migration-, storage-, component-, integration-, e2e-, performance-тестами и физическими проверками.

Эталонные проверки (для будущих этапов):

- осевая мода комнаты длиной 4,5 м при c = 343 м/с — 38,111 Гц;
- длина волны 100 Гц — 3,43 м;
- задержка распространения на 1 м ≈ 2,915 мс;
- два одинаковых когерентных синфазных источника — +6,021 дБ;
- два одинаковых идеальных противофазных источника — полная компенсация;
- Peaking EQ с Gain = 0 — единичная амплитудная передаточная функция;
- идеальный согласованный LR4 — плоская суммарная амплитудная характеристика.

Проверяются: сохранение экспертных параметров при переключении сложности; независимость конфигураций; эквивалентность прежних расчётов при одинаковых входных параметрах; сохранение оригиналов измерений и корректность миграций. WebKit-эмуляция не заменяет физическую проверку iPhone.

Тесты первого пакета: `tests/v2/isolation.test.ts`, `tests/v2/workflows.test.ts` (Vitest, входят в `npm test`), `tests/v2/e2e/shell.spec.ts` (`npm run e2e:v2`).

- `npm run e2e:v2:safari` — те же сценарии в WebKit-эмуляции iPhone; звуковые пропускаются там, где нет Web Audio;
