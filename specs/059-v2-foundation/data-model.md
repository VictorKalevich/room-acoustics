# 059. Модель данных v2

Часть [спецификации v2](spec.md). Это начальные **логические** контракты. Конкретные TypeScript-типы разрабатываются в V2-006, физическая схема хранения — в V2-008, миграция — в V2-009. В первом пакете типов, хранилища и миграции нет.

Модель данных v2 — согласованное исключение из конституции II («общий Project — источник общих данных») только для v2 ([D58](../decisions.md#d58-room-acoustics-v20-утверждённая-спецификация-изоляция-и-первый-пакет--059)). `Project` legacy и формат `.roomacoustics.json` (`FILE_VERSION = 5`) не меняются.

## Предметные сущности

| Сущность | Назначение |
| --- | --- |
| Room | Комната: идентификатор, название, текущая конфигурация, необязательная экспериментальная, общие цели, метаданные |
| RoomConfiguration | Конфигурация: собственный идентификатор, ревизия, геометрия, аудиосистема, слушатели, интерьер, обработка, DSP, настройки симуляции |
| AcousticZone | Акустическая зона: основное помещение и смежные пространства |
| Geometry | Форма помещения: прямоугольник в простом режиме, сложные контуры и пространственные элементы — в продвинутом и экспертном |
| Surface | Поверхность или её сегмент с материалом, поглощением, рассеиванием |
| Opening | Окно, дверь или проём; состояние: закрытая дверь, открытая дверь, постоянный проём, проём с неизвестным соседним пространством |
| RoomObject | Объект плана: интерьер, обработка, оборудование |
| AudioSystem | Конфигурация аудиосистемы: каналы, источники, маршрутизация, кроссоверы |
| EquipmentProfile | Переиспользуемый профиль оборудования (версионируемый); экземпляр в комнате ссылается на версию профиля |
| MaterialProfile | Профиль акустического материала (версионируемый) с источником данных и неопределённостью |
| TreatmentDesign | Конструкция обработки: слои, зазоры, облицовка, размеры, монтаж |

| ListeningArea | Область прослушивания с весом |
| MeasurementDevice | Измерительное оборудование и его калибровки |
| Measurement | Измерение: исходные данные неизменяемы |
| MeasurementSession | Сессия: матрица источников и мест прослушивания |
| MeasurementSnapshot | Неизменяемый снимок модели на момент измерения |
| DSPPreset | Пресет DSP |
| SignalPreset | Пресет тестового сигнала |
| SimulationSettings | Выбор методов, разрешение, параметры расчёта |
| CalculationResult | Результат расчёта с происхождением |
| OptimizationRun | Запуск поиска: временный результат или отчёт, не третья конфигурация |
| Recommendation | Рекомендация общей системы советов |
| ActionPlan | План работ |

## Две конфигурации

- `Room.current` — фактическое состояние, обязательна. `Room.experimental` — виртуальный эксперимент, может отсутствовать.
- Создание эксперимента — полная копия `current` с новым идентификатором конфигурации; дальше конфигурации независимы (общих изменяемых объектов нет).
- Различаться могут: геометрия, материалы, аудиосистема, источники, слушатели, интерьер, обработка, DSP, параметры симуляции.
- Сравнение — режим просмотра двух конфигураций, а не третья конфигурация.
- Рекомендации и результаты оптимизации применяются только к `experimental` после явного подтверждения.
- Подтверждение эксперимента как фактического — отдельная операция; прежняя `current` сохраняется неизменяемым историческим снимком.
- Неизменяемые снимки, отчёты и временные результаты поиска допустимы. Третьей редактируемой конфигурации нет.

## Версионирование

- Версия схемы у каждого хранимого документа и формата файла; миграции — по версиям схемы.
- Ревизия конфигурации — растёт при каждом изменении; результат расчёта хранит ревизию, по которой получен, и признаётся устаревшим при её смене.
- Версия алгоритма — у каждого метода расчёта; результат хранит версию, которой получен (как модель затухания 4 и 5 в D36/D37).
- Профили материалов и оборудования имеют версии. Изменение профиля не меняет задним числом расчёты, отчёты и измерения. Обновление экземпляров в текущих комнатах — явным действием.

## Исторические снимки

- `MeasurementSnapshot` — неизменяемая копия значимой части конфигурации на момент записи.
- Поздняя привязка измерения к комнате помечается как поздняя и не выдаётся за снимок, полученный во время записи.
- При миграции исторические снимки не выдумываются: если у legacy-измерения нет снимка, он отсутствует.
- Подтверждение эксперимента сохраняет прежнюю фактическую конфигурацию как снимок.
- Повторная обработка измерения создаёт новый результат и не меняет исходную запись.

## Система координат

**Принята по [R01](owner-review.md)** — ассистент выбрал её по D59, владелец смотрит решение на ревью: каноническая система v2 совпадает с ядром (см. предложение ниже).

Факты по коду:

- Ядро legacy (`src/core/types.ts`): `x` — глубина от передней стены (у которой колонки) к задней, `y` — от левой стены к правой, `z` — вверх от пола; начало — передний левый нижний угол. `Room` задаёт размеры как `depth` (по `x`), `width` (по `y`), `height` (по `z`). Участки стен: для передней и задней — от левой стены, для левой и правой — от передней.
- Демонстрационные макеты Figma используют иное соглашение о продольной и поперечной осях (по результатам инвентаризации; точное соответствие проверяется по макетам в V2-006).

Принятое решение: каноническая система v2 совпадает с ядром (`x` — от передней стены к задней, `y` — слева направо, `z` — вверх, начало в переднем левом нижнем углу), а виды редактора переводят её в экранные оси. Тогда адаптер не переставляет оси, и эквивалентность прежних расчётов проверяется проще.

## Единицы измерения

Внутренние единицы — СИ, если иное не требует сама величина. Явно различаются:

- метры и сантиметры;
- секунды и миллисекунды;
- герцы;
- линейная амплитуда и энергия;
- децибелы с указанной опорой (dBFS, dB SPL re 20 мкПа, dB re 1 и т. д.);
- градусы и радианы.

Единица — часть контракта поля (тип или имя), а не договорённость в комментарии. dBFS не превращается в SPL без абсолютной калибровки.

## Неизвестные данные

- Неизвестное значение не равно нулю и не заменяется значением по умолчанию молча.
- Состояние «неизвестно» представляется явно и отличается от «не задано пользователем» и «не применимо». Конкретная форма — V2-006.
- Расчёт, которому нужно неизвестное значение, сообщает об ограничении или недоступности, а не подставляет число.
- Неизвестная стоимость не считается нулевой.

## Происхождение результатов

Каждый `CalculationResult`, `Measurement` и производный показатель несёт:

- вид: расчёт, измерение, оценка, демонстрация, импорт;
- метод и версию алгоритма;
- идентификатор и ревизию конфигурации или снимка;
- хеш значимых входных данных;
- калибровку и её версию (для измерений);
- временную привязку и её вид (для измерений);
- предупреждения и ограничения применимости;
- время создания и источник (устройство, файл, приложение).

Интерфейс различает виды результата не только цветом ([docs/acoustic-lab.md](../../docs/acoustic-lab.md)).

## Хранение v2

Отдельная IndexedDB v2 (имя — V2-008, не совпадает с базами legacy `room-acoustics`, `ra.noiseHistory`, `ra.micCalibration`). Логические области:

`rooms`, `measurements`, `measurementData`, `snapshots`, `materials`, `equipment`, `measurementDevices`, `constructions`, `presets`, `calculations`, `optimizationRuns`, `actionPlans`, `reports`, `meta`.

Физическая схема определяется позднее. Для объёмных данных — OPFS при подтверждённой совместимости. Браузерное хранилище не считается гарантированно постоянным; резервная копия — полная.

## Миграция из legacy

Предлагаемое направление (V2-009):

- Источник — проекты legacy (IndexedDB `room-acoustics` и файлы `.roomacoustics.json` всех поддерживаемых версий); старые форматы остаются импортируемыми.
- `Project.room`, `sources`, `constraints`, `current` → `Room` с `current`-конфигурацией через адаптер.
- `Project.setups` → архив исторических вариантов; выбранный вариант восстанавливается в эксперимент. Не создавать из них редактируемые конфигурации.
- Замеры в `Setup.measurement` и `history` → `Measurement` с происхождением «перенесено из проекта legacy»; снимок состояния комнаты на момент записи не выдумывается.
- История шумомера и каталог калибровок legacy — отдельные базы; v2 читает их, не изменяя.

Правила:

- не изменять legacy-хранилище; сохранять оригиналы;
- проверять данные перед преобразованием;
- повторный запуск не создаёт дубликаты;
- изменённые данные v2 не перезаписываются без согласия;
- сохраняются пользовательские варианты, ссылки и происхождение измерений;
- исторические снимки не выдумываются;
- формируется отчёт о проблемах миграции;
- корректно обрабатываются неудачное чтение, запись, квоты и повреждённые данные;
- автоматической миграции при запуске оболочки нет (в первом пакете оболочка вообще не читает хранилище).
