# 059. Решения, требовавшие участия владельца — на ревью

По указанию владельца от 27.11.2026 ([D59](../decisions.md#d59-редизайн-v2-целиком-коммит-и-push-после-каждого-шага-решения-на-ревью--059)) вопросы, где нужно решение владельца, ассистент решает сам. Он выбирает вариант, который считает лучшим, применяет его и записывает сюда. Список показывается владельцу на ревью после окончания всей фичи. Любое решение можно пересмотреть: в строке указано, где оно применено и как его откатить.

| № | Вопрос | Выбрано | Почему | Где применено / как пересмотреть |
| --- | --- | --- | --- | --- |
| R01 | Система координат v2 | Как в ядре: `x` — от передней стены (у колонок) к задней, `y` — от левой стены к правой, `z` — вверх; начало — передний левый угол у пола. Виды редактора сами переводят её в экранные оси | Адаптер не переставляет оси, поэтому эквивалентность прежних расчётов проверяется напрямую; меньше места для ошибок знака | `src/v2/domain`, `src/v2/adapters`; смена — в домене и адаптере, с тестами эквивалентности |
| R02 | Куда коммитить отложенное во время работы над v2 | Отдельным коммитом только с `specs/deferred.md` в `redesign/v2` и push ветки, а не в `main` | Указание «коммит и push после каждого шага» относится к ветке редизайна, `main` меняется только финальным merge | AGENTS.md, раздел v2 |
| R03 | `can_admins_bypass: true` у окружения `github-pages` | Не менять: ассистент не меняет настройки репозитория | Это настройка инфраструктуры, без доступа владельца её не изменить; защита workflow и политика веток уже есть | Настройки репозитория → Environments → github-pages |
| R04 | Уязвимости moderate в dev-зависимостях (`vite-plugin-pwa`→`workbox-build`, `yaml`) | Не обновлять в рамках редизайна | `npm audit` предлагает понизить `vite-plugin-pwa` до 1.1.0 — риск для PWA legacy. Пакеты не попадают в бандл | [deferred.md](../deferred.md), отдельная задача |
| R05 | Публикация v2 при финальном merge в `main` | Merge в `main` публикует на Pages только legacy-сборку (`deploy.yml` собирает `dist/`). Оболочка v2 на Pages не выкладывается | V2-060 требует отдельного утверждения публикации v2; merge кода её не подразумевает. Действующее приложение остаётся рабочим | `deploy.yml`; публикация v2 — отдельным решением (отдельный origin или scope) |
| R06 | Push коммита V2-004 (`.github/workflows/*`) отклонён GitHub: у сохранённого токена Git (GCM 2.9.1) нет права `workflow` | Держать коммит в локальной ветке `v2-workflow-commit` (deploy.yml с защитой по ветке, v2-check.yml, tests/v2/workflows.test.ts). Остальную работу пушить в `redesign/v2`; коммит перенести поверх ветки, когда токен получит право `workflow`, и до финального merge | Другого способа отправить изменение workflow без участия владельца нет. Пока коммита нет на GitHub, `deploy.yml` в ветке прежний: push в `redesign/v2` его и так не запускает (`branches: [main]`), CI для ветки не работает | Владельцу: `git credential-manager github login` (или новый токен с правом `workflow`), затем `git cherry-pick v2-workflow-commit` и push |
| R07 | Открытый проём выше пола (открытое окно) и проём к неописанному пространству: ядро знает только открытые проёмы от пола | Адаптер передаёт приподнятый проём в ядро проёмом от пола той же ширины и площади (высота = верх − низ), проём к неописанному пространству — как открытый в большой объём; в обоих случаях результат несёт предупреждение | Формулы ядра не меняются (D59), площадь поглощения сохраняется; ошибка — только в положении участка по высоте для модального расчёта. Молчаливой подмены нет | `src/v2/adapters/core.ts` (`splitOpenings`); точная модель — в V2-048 (расширенные модели) |
| R08 | У одного проекта legacy несколько копий (рабочий проект, запись при уходе, сохранённая копия) | Переносится самая свежая по времени изменения; при равенстве — рабочий проект. Старые копии не переносятся, остаются в legacy и перечисляются в отчёте | Одна комната на проект без дубликатов; legacy не меняется, поэтому ничего не теряется | `src/v2/storage/legacySource.ts` (`pickCandidates`) |
| R09 | Откуда переносить, если v2 открыта на другом origin, чем legacy | Перенос из IndexedDB — только на том же origin; на другом — из файла `.roomacoustics.json` («Экспорт» в legacy). Автоматического переноса при запуске нет | Браузер не даёт читать хранилище чужого origin; файл работает везде | `src/v2/application/migration.ts`; при публикации v2 (V2-060) — выбрать origin |
