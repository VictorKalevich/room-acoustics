# 039 — Обрезанный PLY отвергается с понятной ошибкой

Статус: реализовано 2026-11-16. Основание: [D34](../decisions.md).
Скан PLY, данных в котором меньше, чем заявлено в заголовке (файл не докопирован или не докачан), отвергается с
сообщением, что файл обрезан. Остальные форматы и исправные PLY читаются как прежде.

## Задача владельца

2026-11-16, после аудита тестов ([038](../038-test-audit/spec.md)): исправить ошибку загрузчика из
[отложенного](../deferred.md) — обрезанный PLY с гранями называется облаком точек — вместе с тестами на исправные и
обрезанные PLY. Владелец спросил, может ли исправление сломать чтение других форматов; ответ — нет (ниже,
«Границы»). При проверке выяснилось, что ошибка шире записанной (ниже, «Поведение до»); владелец выбрал вариант
«отклонять любой обрезанный PLY, как STL».

## Поведение до (проверено запуском `loadScan` на синтетическом скане 5 × 4 × 2,6 м)

| Файл | Было |
| --- | --- |
| Текстовый, обрыв среди точек или граней | загружается часть скана; при потере больше половины граней — «Не удалось найти четыре стены. Отсканируйте стены целиком…»; при меньшей потере — размеры по части скана, без предупреждения |
| Текстовый, нет последней грани | загружается без неё |
| Текстовый, почти ничего нет (заявлено 1000 точек и 2000 граней, записано 3 и 1) | «В файле нет поверхностей (или это облако точек). Экспортируйте скан как сетку (mesh).» |
| Двоичный, любой обрыв | «Не удалось прочитать файл (PLY). Поддерживаются: …» — будто формат не поддерживается |

## Требования

- FR-3901: если в PLY данных меньше, чем заявлено в заголовке, загрузка отклоняется с `ScanError`: «Файл PLY обрезан
  или повреждён: в заголовке N точек и M граней, а данных меньше. Скопируйте или экспортируйте файл заново.» (N и M —
  из заголовка). Так же, как для двоичного STL.
- FR-3902: текстовый PLY — строк данных не меньше суммы строк всех элементов заголовка, а в последней строке
  значений не меньше, чем требуют свойства её элемента (у списка — число и столько значений). Двоичный (оба порядка
  байтов) — данные всех элементов, со списками переменной длины, помещаются в файл.
- FR-3903: исправные PLY читаются как прежде: текстовые и двоичные, с переводами строк Windows, без перевода строки в
  конце, с лишними байтами в конце двоичного, с четырёхугольными гранями, дополнительными свойствами вершин и лишними
  элементами. Облако точек без граней — прежняя ошибка.
- FR-3904: если заголовок не разобрать (нет `end_header`, нецелое число строк, неизвестный тип свойства), решает
  загрузчик three.js, как прежде.

## Границы

- Меняется только ветка PLY в `src/scan/load.ts` (проверка `checkPly` перед разбором). Определение формата, ветки OBJ,
  STL и glTF/GLB и общая часть после разбора (треугольники, «нет поверхностей», очистка, распознавание) не меняются.
- Обрыв внутри последнего числа текстового файла не обнаруживается: такой файл неотличим от целого без перевода
  строки в конце.
- Ошибка «испорченный glTF/GLB получает совет про внешние файлы» в задачу не входит и остаётся в отложенном.

## Приёмка

1. Тесты FR-3901–FR-3903 в `tests/scan/badfiles.test.ts`; тесты обрезанного PLY без исправления падают.
2. `npm test`, `npm run lint`, `npm run build`, `npm run e2e` проходят.
3. Пункт отложенного об обрезанном PLY закрыт; контракт импорта скана дополнен.

## Реализация и проверка

2026-11-16:

- `src/scan/load.ts`: `plyHeader` разбирает заголовок (формат, элементы, свойства, начало данных), `checkPly`
  проверяет полноту данных: в текстовом — число непустых строк и значения последней строки, в двоичном — проход по
  элементам (без списков — сразу по размеру строки, со списками — по числам в строках).
- `tests/fixtures/synthetic.ts`: `toPLY` — текстовый и двоичный PLY (оба порядка байтов, число вершин грани `uchar`
  или `int`).
- `tests/scan/badfiles.test.ts`: исправные PLY (пять вариантов записи) дают все 7 754 треугольника и комнату
  5 × 4 × 2,6 м; четырёхугольные грани с нормалями, цветами и лишним элементом — 32 треугольника; двоичный с лишними
  байтами читается; обрывы текстового (среди точек, среди граней, без последней грани, последняя грань без номера) и
  двоичного (среди точек, среди граней, без последнего байта, оба порядка байтов) — точный текст FR-3901.
- Без исправления в `src/scan/load.ts` оба теста обрезанного PLY падают, тесты исправных проходят.
- `npm test` — 507 тестов в 59 файлах; `npm run lint` и `npm run build` — без ошибок; `npm run e2e` — 96 сценариев и
  подготовка комнаты проходят в эмуляции iPhone в Chrome (сценарии сканов — с OBJ и STL; PLY в e2e не загружается).
  WebKit и физический iPhone не проверялись.
