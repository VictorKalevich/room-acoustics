## Снимок комнаты `NoiseRoomSnapshot` v1

Хранится в `NoiseRecord.context.room`, только у записи со связью с проектом. Создаётся `roomSnapshot(room, modes, fMax, schroederHz)` при «Начать» шумомера из списка `App`.

| Поле | Значение |
| --- | --- |
| `version` | `1` |
| `model` | `'rect-rigid'` — прямоугольная комната с жёсткими стенами |
| `depth`, `width`, `height` | размеры комнаты проекта, м (> 0) |
| `temperatureC` | температура проекта, °C; c = 331,3·√(1 + T/273,15) выводится при показе |
| `approximate` | у комнаты скос, пристройка или волновая модель (`isWave`) |
| `schroederHz` | частота Шрёдера проекта (`computeReverb`), Гц |
| `fMax` | верхняя частота списка: min(500, max(200, fШ)), Гц |
| `modes` | `{ f, n: [nx, ny, nz], kind }[]` — список `computeModes`, по возрастанию f, без пересчёта |

Проверка `checkRoomSnapshot` (сохранение, чтение, импорт): версия и модель, положительные размеры, fШ и fMax, конечная температура. Не больше 20 000 мод. Каждая мода: f > 0, не убывает, не выше fMax, индексы — неотрицательные целые, тип соответствует числу ненулевых индексов. Снимок без `project` — ошибка записи. Числа мод не пересчитываются: снимок хранит то, что было показано.

Объём JSON (измерено 23.11.2026 скриптом в Vitest):

| Комната | fШ / fMax | Мод | Объём |
| --- | --- | --- | --- |
| 5 × 4 × 2,5 м | 202 / 202 Гц | 68 | 3,9 КБ |
| 8 × 6 × 3,5 м | 131 / 200 Гц | 195 | 10,8 КБ |

Крайний случай — fMax 500 Гц, если fШ ≥ 500 Гц. Для 5 × 4 × 2,5 м это 801 мода и 44 КБ. Снимок хранится в теле записи и в заголовок списка не попадает.

Совместимость: поле необязательное. Записи 056 без него читаются. `NOISE_RECORD_FORMAT` и schema 4 не повышались, потому что блок 2 не опубликован. `sameRoom(a, b)` сравнивает размеры, температуру и признак приближения: при равенстве список мод тот же.

## Маркеры

`modeMarkers(modes, { lo, hi, kinds, max = 24 })`: моды в [lo, hi] выбранных типов. При избытке берутся сначала осевые, затем тангенциальные, затем косые, внутри типа по частоте; результат сортируется по частоте. Возвращается и общее число в диапазоне. lo = 20 Гц, hi — верх видимого диапазона графика (250 Гц или min(20 кГц, fs/2)).

## Поиск пиков `spectralPeaks(density, binHz, { lo, hi, frames })`

Вход — PSD, которую показывает график (`spectral.average(period, weight, corrected)`), без сглаживания; frames = ⌊секунды·fs / 16384⌋.

1. frames < 24 → отказ `frames`. 24 кадра 32768 с шагом 16384 при коэффициенте перекрытия окна Ханна 1/6 дают около 23 независимых усреднений, разброс бина около ±1 дБ. Одиночный кадр не используется.
2. Границы: от max(lo, 10 Гц + 8 бинов) до min(hi, последний бин − 8). Пустой интервал → отказ `range`.
3. Кандидат — бин k, строго больше бинов k−3…k−1 и не меньше k+1…k+3.
4. Фон — медиана симметричного окна k ± s без бинов k ± 3, где s = min(max(12, round(0,1225·k)), k − ⌈10 Гц/binHz⌉, N − 1 − k). 0,1225·k — половина трети октавы. Симметрия убирает сдвиг медианы на наклоне спектра.
5. Выраженность — 10·lg(PSD[k] / медиана). Пик — при ≥ 6 дБ. Остаются 8 самых выраженных, по возрастанию частоты.
6. Частота пика — k·binHz, разрешение — шаг спектра.

Верхняя граница сопоставления в интерфейсе — `matchUpper`: min(верх графика, fШ, fMax).

## Возможные соответствия `matchPeaks(peaks, modes, binHz)`

Допуск δ = 0,03·f_пика + binHz. Кандидаты — все моды снимка любого типа с |f_моды − f_пика| ≤ δ, по возрастанию |Δf|. Каждому пику соответствует список; утверждения о причине нет.

Проверено (Vitest): тон на средней PSD находится в пределах одного бина при 48 и 44,1 кГц. Белый шум 30 с (Z и A, 20–500 Гц) пиков не даёт. Тон на осевой моде (1, 0, 0) находит её среди возможных соответствий; тон на 27 Гц в комнате с первой модой 34,3 Гц соответствий не имеет. Для отказов, допуска и порядка кандидатов — отдельные тесты.

## Журнал входа и окружение (диагностика шумомера)

В `NoiseDiagnostics` (поле `path` прежнего JSON и `capture` снимка сеанса) добавлены:

- `environment: { displayMode: 'standalone' | 'browser' | null, appleStandalone: boolean | null }` — `matchMedia('(display-mode: standalone)')` и `navigator.standalone`. Без UA и без отпечатка устройства;
- `events: { atMs, type, state? }[]` — `mute`, `unmute`, `ended`, `devicechange`, `context` (со `state` AudioContext). Время — мс от открытия входа, не больше 32 событий. Журнал пишут слушатели потокового `openMic`; после закрытия входа записи прекращаются.

Импорт schema 2/3 по-прежнему переносит из `path` только разрешённые поля: окружение и журнал при этом отбрасываются. В снимке schema 4 они сохраняются как есть и показываются после проверки формы.
