# 056 · структура истории шумомера, форматы и совместимость

Код:

- `src/core/noiseRecord.ts` — запись, проверка, заголовок, просмотр, предупреждения;
- `src/core/noiseFile.ts` — schema 2/3 и 4, импорт;
- `src/core/noiseCsv.ts` — CSV;
- `src/core/noiseCompare.ts` — сравнение;
- `src/state/noiseHistory.ts` — IndexedDB.

Снимок сеанса — [`NoiseSessionV1` из 055](../055-noise-timeline/data-model.md), без изменений.

## Запись `NoiseRecord` (формат записи 1)

| Поле | Содержание |
| --- | --- |
| `id` | `[A-Za-z0-9-]{8,64}`: UUID сеанса или `legacy-<16 hex>` для импорта schema 2/3 |
| `name` | Название, до 100 символов; можно переименовать |
| `savedAt` | Момент сохранения или импорта, ISO UTC |
| `project` | `null` или `{id, name}` проекта на момент сохранения: только сведения |
| `imported` | `null` или `{at, file, schema}`: когда, из какого файла и какой схемы |
| `context.view` | Вес, период и вид спектра на экране в момент сохранения: начальное представление записи |
| `context.input` | `null` или `{source: 'system' \| 'selected', confirmedModel}`. Идентификатор устройства не хранится |
| `context.absolute` | `null` или `{offsetDb, verifiedAt, references}`: абсолютная привязка, только если она была действительна для этого входа и тракта. Только сведения, уровни остаются dBFS |
| `context.ranges` | Экстремумы RMS: Z по блокам 4096, A/C по кадрам. Из снимка не выводятся. У импорта — `null` |
| `content` | `{type: 'session', session: NoiseSessionV1}` или `{type: 'legacy', legacy: LegacyNoiseV1}` |

Содержимое неизменяемо. Переименование меняет только `name` в заголовке. `session.meta.name` остаётся названием на момент записи.

### `LegacyNoiseV1` — импорт schema 2/3

- `schema`, `sampleRate`, `name`, `date`, `status`, `manual`, `build`, `audioStartMs`;
- `capture` — только известные поля диагностики;
- `blocks` — колонки `NoiseBlocksData`, точно из `history`;
- `spectrum` — `null` или один спектр:
  - вес и период;
  - `seconds`, `psd` (16385 бинов или `null`);
  - `leqPower`, `leqSeconds`;
  - `rmsPower` — экстремумы этого веса;
  - `sessionPeakAmplitude`;
- `calibration` (schema 3) — снимок профиля, `model`, `maxBoostDb`, спектр с поправкой.

## Представления

| Представление | Сеанс (055) | Импорт schema 2/3 |
| --- | --- | --- |
| Сводка, Leq Z | из `totals` | из RMS блоков (средняя мощность блока) или `leqPower` при весе Z |
| Leq A/C | `totals.weightedPower` | только вес файла |
| Экстремумы RMS | `context.ranges` | вес файла; Z — по блокам |
| История RMS блоков | `blocks` | `blocks` (точно) |
| PSD, LTAS, полосы: любой вес и период, исходный или с поправкой | `spectra` × `weightPower` × `powerGains` снимка, побитно как `NoiseSpectrum` | только вес и период файла |
| Спектрограмма, Leq 1/10/60 с, Leq с начала, пик за секунду, история полос | `timeline` | **недоступны** |
| Калибровка | снимок профиля | снимок schema 3 |
| Диагностика | `capture` | `capture` |

Производные (уровни дБ, окна, доли, цвета, сводки списка, предупреждения) не хранятся: они выводятся при просмотре. Выводимы — всё, что получается из сумм снимка. **Не выводимы**:

- PCM, отдельные кадры старше 10 мин (у спектрограммы старше 10 мин — средние за 10 с);
- спектры A/C/Z на моменты, кроме сохранённых периодов на момент остановки;
- у импорта schema 2/3 — всё, чего нет в файле.

Просмотр не синтезирует недоступные представления: в интерфейсе для них — «нет данных».

## IndexedDB `ra.noiseHistory`, версия 1

| Хранилище | Ключ | Значение |
| --- | --- | --- |
| `headers` | `id` | `NoiseRecordHeader`: `id`, `format` 1, `name`, `savedAt`, `startedAt`, `activeSeconds`, `spanSeconds`, `sampleRate`, `source`, `sourceVersion`, `leq {Z, A, C}` (средняя мощность FS²), `spectrumWeight`, `calibration {id, version, name}`, `absolute`, `bytes`, `project`, `imported`, `build`, `missingBlocks`, `clippedBlocks` |
| `bodies` | `id` | `{id, format: 1, context, content}` — типизированные массивы как есть (structured clone) |

- Одна транзакция на операцию над обоими хранилищами. Исключение в обработчике отменяет транзакцию.
- Новые версии базы добавляют хранилища по `oldVersion`. Существующие записи не переписываются. База более новой версии — ошибка «обновите приложение» без изменения данных.
- Тело другого `format` — ошибка «другая версия формата истории».
- Повреждения в списке:
  - заголовок не прошёл проверку — `header`;
  - нет тела — `body`;
  - тело без заголовка — `orphan`.

  Такие записи не открываются, их можно удалить.

## Пределы и память

| Предел | Значение | Зачем |
| --- | --- | --- |
| Массивы одной записи | 48 МиБ | 12 ч при 48 кГц с профилем ≈ 38 МиБ ([055](../055-noise-timeline/data-model.md#проверка-и-объём)) |
| Вся история | 512 МиБ | Ограничить долю квоты сайта |
| Число записей | 500 | Список и проверки остаются быстрыми |
| Файл импорта | 64 МиБ | Schema 4 для 12 ч с профилем ≈ 51 МиБ |
| CSV спектрограммы | 1 млн ячеек | 12 ч по 10 с × 120 полос ≈ 0,52 млн |
| Название | 100 символов | Как поле «Название измерения» |

Измерено на Windows (Node, синтетический тон 600 с при 48 кГц, полный тракт `NoiseMeter`):

| | Без профиля | С профилем |
| --- | --- | --- |
| Массивы записи | 3,26 МиБ | 5,80 МиБ |
| Расширенный JSON | 4,35 МиБ | 7,74 МиБ |
| Прежний JSON schema 2/3 | 1,79 МиБ | 2,16 МиБ |
| Экспорт schema 4 / импорт | 0,12 / 0,02 с | 0,21 / 0,04 с |

На iPhone время и память не измерялись.

- **Политика памяти**: записи не загружаются целиком в список — только заголовки. Тело читается при открытии записи или выборе в сравнении и освобождается при закрытии. Живой сеанс в памяти — как в 055, до «Сбросить» или нового запуска.
- **Политика хранения**: автоматического удаления нет. Переполнение — отказ в сохранении с причиной; место освобождается удалением вручную. Сохранность не гарантируется: браузер может очистить данные сайта, поэтому для резервной копии — расширенный JSON. `persist()` запрашивается при явном сохранении.

## Расширенный JSON schema 4

```json
{
  "kind": "room-acoustics/noise-export", "schema": 4,
  "exportedAt": "ISO", "exportBuild": {"sha", "time"},
  "note": "…dBFS, не дБ SPL. Запись звука не входит.",
  "encoding": "Типизированные массивы: {\"$typed\", \"length\", \"base64\"} — байты little-endian, base64 RFC 4648.",
  "record": {"id", "name", "savedAt", "project", "imported", "context", "content"}
}
```

- Типизированные массивы — `{"$typed": "Float64Array" | "Float32Array" | "Uint32Array" | "Uint16Array" | "Uint8Array", "length": n, "base64": "…"}`. Значения NaN (нет данных в `blocks.rms`) переносятся побитно.
- Заголовок списка в файл не входит: при импорте он выводится заново.
- При импорте поле `imported` заменяется сведениями нового импорта, остальное проверяется `checkRecord`.
- Номер `schema` 4 продолжает нумерацию экспортов шумомера. Смысл полей schema 2/3 не менялся. `kind` отличает файл от прежних экспортов, файла проекта (`format: room-acoustics-project`) и снимка 055 (`room-acoustics/noise-session`).

## Совместимость со старыми экспортами

- Schema 2 и 3 всех сборок 052–055 импортируются. `endSeconds = next·4096/fs` и `peakHz = bin·fs/4096` вычислялись одной и той же формулой до и после 055 и проверяются на точное равенство сетке. Ошибочные или подменённые значения отвергаются.
- Schema 1 (этап A) не содержит истории: отказ с объяснением.
- Поля `measurement.f/db` (спектр модуля последнего блока), `bands` и `error` не переносятся. Полосы выводятся из PSD.

## Пределы сравнения

- Сравниваются только записи одного веса. Разные веса — запрет.
- Разные частоты дискретизации, периоды, поправки и входы — пометки:
  - энергия приводится к полосам 1/12 октавы до общего Найквиста (`spectrogramEdges(min fs)`);
  - полосы уже бина FFT не повышают разрешение.
- Leq сравнивается по весам, которые есть у обеих записей.
- dBFS не переводится в SPL, абсолютная привязка не применяется.
- Текущий профиль каталога к записям не применяется.
