# Research: Акустический калькулятор комнаты (MVP)

Все решения приняты для ограничений конституции: только клиент, Safari на iPhone,
тестируемое ядро, минимум зависимостей.

## R1. Доступ к LiDAR из браузера

- **Decision**: Сканирование выполняется сторонним приложением; мы импортируем файл.
- **Rationale**: Safari на iOS не поддерживает WebXR Device API и не даёт доступа к ARKit/LiDAR.
  RoomPlan доступен только нативным Swift-приложениям.
- **Alternatives considered**: нативный сканер на RoomPlan (нужен Mac и переподписание каждые
  7 дней) — отложено, может стать отдельной фичей.

## R2. Форматы скана и парсинг

- **Decision**: OBJ, GLB/glTF (встроенные буферы), PLY (ASCII/бинарный), STL (ASCII/бинарный)
  через загрузчики three.js (`OBJLoader`, `GLTFLoader`, `PLYLoader`, `STLLoader`). Парсинг в
  основном потоке (GLTFLoader декодирует текстуры через DOM API), затем массив позиций
  треугольников передаётся в Web Worker (transferable) для анализа.
- **Rationale**: зрелые проверенные парсеры; three.js и так нужен для 3D-превью.
- **Alternatives considered**: собственные парсеры (больше кода и ошибок); USDZ — стандартный
  загрузчик three.js не читает бинарный USDC, который пишут сканеры, поэтому вне скоупа.

## R3. Распознавание прямоугольной комнаты из сетки

- **Decision**: детерминированный алгоритм на гистограммах, без ML:
  1. Ось «вверх»: среди ±X, ±Y, ±Z выбирается ось с наибольшей площадью треугольников,
     нормаль которых почти параллельна оси (|n·a| > 0,9) и которые лежат в двух крайних
     пиках высот (пол и потолок); затем вектор уточняется усреднением нормалей пола
     (компенсация наклона).
  2. Пол/потолок: площадь-взвешенная гистограмма высот горизонтальных треугольников
     (шаг 1 см, сглаживание 3 см); пол — нижний значимый пик, потолок — верхний.
  3. Ориентация стен: для вертикальных треугольников (|n·up| < 0,2) — площадь-взвешенное
     среднее (cos 4θ, sin 4θ) угла нормали в горизонтальной плоскости; φ = atan2/4.
     Свёртка по 90° делает стены X и Y одним кластером.
  4. Положение стен: в повёрнутой системе — гистограммы координат центров вертикальных
     треугольников с нормалями вдоль X и вдоль Y, только из верхней половины высоты комнаты
     (там почти нет мебели); стены — крайние значимые пики (≥ 15 % от максимального).
  5. Единицы: по сырой высоте (1,8–5 → м; 180–500 → см; 1800–5000 → мм).
  6. Уверенность: покрытие каждой стены (площадь в пике / ожидаемая площадь верхней
     половины), доля вершин за пределами найденного объёма (> 15 см), наличие потолка.
- **Rationale**: прозрачен, тестируется на синтетических сетках, быстрый (линейный по числу
  треугольников), устойчив к мебели за счёт верхней половины стен.
- **Alternatives considered**: RANSAC плоскостей (недетерминирован, медленнее на 1–2 млн
  треугольников); минимальный ориентированный ограничивающий прямоугольник (ломается на
  проёмах и выступающей мебели).

## R4. Модальная модель отклика

- **Decision**: модальная сумма для прямоугольной комнаты (Morse & Ingard; Kuttruff,
  *Room Acoustics*, гл. 3). Передаточная функция от точечного источника постоянной
  объёмной скорости в r₀ к точке r:

  H(ω) = jω · Σₙ ψₙ(r)·ψₙ(r₀) / (Λₙ · (ωₙ² − ω² + 2jδₙω)),
  ψₙ = cos(nₓπx/L)·cos(n_yπy/W)·cos(n_zπz/H), Λₙ = Π(1 при nᵢ = 0, иначе ½).

  Суммирование по модам до 1,5 × верхней частоты расчёта.
- **Затухание мод**: δₙ = (c / 8V) · (εₓAₓ + ε_yA_y + ε_zA_z) / 2, где A_i — эквивалентная
  площадь поглощения пары стен, перпендикулярных оси i, εᵢ = 2 при nᵢ > 0, иначе 1
  (Kuttruff). Нормировка /2 выбрана так, что для косых мод δ совпадает со значением Сэбина
  δ = cA/(8V) = 6,91/T₆₀. Поглощение мебели распределяется пропорционально площадям.
  Коэффициенты α(f) интерполируются по логарифму частоты между октавными полосами.
- **Rationale**: точна ниже частоты Шрёдера для прямоугольной комнаты, дёшева
  (≈ 150 мод × 100 частот), учитывает фазу и полосы источников.
- **Alternatives considered**: метод мнимых источников (дороже, нужен для высоких частот),
  FDTD/МКЭ (слишком тяжело для телефона и для простоты).

## R5. Реверберация и частота Шрёдера

- **Decision**: Сэбин T = 0,161V/A и Эйринг T = 0,161V / (−S·ln(1 − ᾱ)) по октавам
  63–4000 Гц, плюс поглощение воздуха 4mV для 2 и 4 кГц (ISO 9613-1 при 20 °C, 50 %).
  Основная — Эйринг, если ᾱ > 0,2, иначе Сэбин. f_S = 2000·√(T_mid/V), T_mid — среднее
  500 и 1000 Гц. Скорость звука c = 331,3·√(1 + t/273,15).
- **Rationale**: стандартные формулы, легко проверить вручную (SC-002).

## R6. Материалы

- **Decision**: справочник из 16 материалов (бетон, штукатурка, кирпич, гипсокартон, стекло,
  деревянные панели, паркет, деревянный пол на лагах, линолеум, плитка, ковёр тонкий/толстый,
  шторы, акустические панели 50 мм, подвесной акустический потолок, окрашенный бетонный
  потолок) по сводным таблицам (Everest & Pohlmann, *Master Handbook of Acoustics*;
  Long, *Architectural Acoustics*). 63 Гц — экстраполяция (значение 125 Гц), помечено.
  Отдельный параметр «меблировка» (пустая / обычная / много мягкой мебели) добавляет
  эквивалентную площадь поглощения на м² пола — оценочные значения, указаны как оценка.
- **Rationale**: без мебели жилая комната с бетонными стенами даёт нереалистичный
  T₆₀ > 2 с; меблировка приближает к типичным 0,4–0,7 с.

## R7. Фильтры источников

- **Decision**: если есть сабвуфер и нижняя граница колонок совпадает с верхней границей
  сабвуфера (±15 %), это кроссовер: Linkwitz–Riley 4-го порядка (ФНЧ сабвуфера, ФВЧ колонок).
  Иначе естественный спад: ФВЧ Баттерворта 2-го порядка на нижней границе (закрытый ящик),
  ФНЧ 2-го порядка на верхней. Комплексные передаточные функции, суммирование с фазой.
- **Rationale**: отражает реальный стык сабвуфера и колонок; полоса источника определяет,
  где он влияет на оценку (FR-013/FR-014).

## R8. Метрика и поиск расстановки

- **Decision**:
  - Целевая АЧХ — сумма фильтров источников в свободном поле. Отклонение в комнате —
    20·log₁₀|H_room| − 20·log₁₀|H_target| на сетке 1/24 октавы от f_lo = max(20 Гц, нижняя
    граница системы) до f_hi = clamp(f_S, 120, 300) Гц; среднее вычитается.
  - Оценка = СКО отклонения (дБ) в центре зоны прослушивания (вес 0,6) + среднее СКО в двух
    точках ±0,3 м по ширине (вес 0,4) — устойчивость к сдвигу головы; плюс геометрические
    штрафы для колонок: угол раскрытия вне 50–70° (0,1 дБ на градус), расстояние до
    передней стены с четвертьволновым провалом c/(4d) в диапазоне (f_S, 500 Гц) — 0,5 дБ.
    Меньше — лучше.
  - Поиск: дискретная сетка. Слушатель — по оси симметрии комнаты, шаг 5 см внутри
    разрешённой зоны. Колонки — симметричная пара: расстояние до передней стены и
    полуразнос, шаг 10 см. Сабвуферы — кандидаты вдоль стен (шаг 25 см, 15 см от стены) и в
    углах; 1–2 сабвуфера перебираются полностью, 3–4 — жадно с последующим уточнением.
  - Порядок: для каждого слушателя предвычисляются передаточные функции всех кандидатов
    (модальная сумма один раз на точку), затем лучшие 5 конфигураций колонок, затем
    сабвуферы; итог — топ-3 различающихся варианта (по слушателю и сабвуферам).
  - Расчёт в Web Worker с сообщениями о прогрессе.
- **Rationale**: метрика СКО отклонения — общепринятая для оценки модальной неровности
  (Welti & Devantier, «Low-Frequency Optimization Using Multiple Subwoofers», JAES 2006);
  сетка гарантирует воспроизводимость и укладывается в 10 с.
- **Alternatives considered**: генетические алгоритмы/отжиг (недетерминированы, сложнее
  тестировать); оптимизация задержек и EQ (вне скоупа MVP).

## R9. Стек приложения

- **Decision**: TypeScript (strict) + Vite (сборка в статику) + Preact (UI, ≈ 4 КБ) +
  three.js (загрузчики и 3D-превью, подгружается лениво только на экране скана) +
  vite-plugin-pwa (манифест и service worker с precache) + Vitest (тесты) + Playwright
  (сквозная проверка в эмуляции iPhone). Графики — собственные SVG-компоненты.
  Хранение — IndexedDB через небольшую собственную обёртку.
- **Rationale**: каждая зависимость закрывает конкретную задачу (принцип VI): Preact —
  управление состоянием множества форм без ручного DOM; three.js — парсеры форматов и
  WebGL; vite-plugin-pwa — корректный список precache с хешами файлов.
- **Alternatives considered**: чистый DOM (много шаблонного кода для форм), React
  (тяжелее без выгоды), Chart.js (лишняя зависимость ради двух графиков).

## R10. Хостинг и проверка на iPhone

- **Decision**: сборка в `dist/` — статические файлы, базовый путь относительный (`./`),
  чтобы работать на GitHub Pages в подкаталоге или любом HTTPS-хостинге. Для быстрой
  проверки — превью-публикация; для офлайн-режима и установки на домашний экран —
  GitHub Pages (нужен HTTPS для service worker).
