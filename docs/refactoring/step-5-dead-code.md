# Шаг 5. Удаление неиспользуемых файлов

Часть [плана рефакторинга](../refactoring-roadmap.md). Общие ограничения, порядок работы и проверки описаны
там; здесь только особенности шага. Факты сверены с кодом 2026-11-14 на коммите `575e574`.

## Зачем

После переносов 018, 022 и 024 остались файлы-ссылки на прежние пути. Их никто не импортирует, но они
попадают в поиск и подсказки и создают впечатление двух мест для одного компонента.

## Что установлено

Граф импортов `src` (включая динамические импорты и `new URL` для воркеров) показывает, что эти файлы
никем не импортируются:

| Файл | Что это |
| --- | --- |
| `src/ui/components/ActionMenu.tsx`, `CalculationStatus.tsx`, `ConfirmSheet.tsx`, `Fields.tsx`, `SectionNav.tsx` | Переэкспорты из `src/ui/design-system` (018) |
| `src/ui/screens/RoomFirst.tsx` | Переэкспорт из `Gates.tsx` (022) |
| `src/ui/screens/SyncScreen.tsx` | Переэкспорт `ProjectsScreen` (024); в файле написано «файл можно удалить» |

Ссылки на них остались в документах: [docs/design-system.md](../design-system.md) (строка про «старые
пути»), [docs/ui-refactor.md](../ui-refactor.md) («Ответственность модулей» называет
`src/ui/components/SectionNav.tsx` и `CalculationStatus.tsx`), [specs/current-state.md](../../specs/current-state.md)
(«Старые пути общих компонентов — совместимые переэкспорты»), а также в исторических спецификациях 017, 021
и 024.

## Что должно получиться

- Перечисленные семь файлов удалены.
- Документы текущего состояния (`docs/design-system.md`, `docs/ui-refactor.md`, `specs/current-state.md`)
  называют действующие пути. В исторических спецификациях ссылки на удалённые файлы заменены действующими
  или помечены как прежние — без переписывания истории этапа.

## Поведение

Не меняется: файлы не входят в сборку.

## Границы

`deploy/github-pages.yml` **не удалять**. Он отличается от рабочего `.github/workflows/deploy.yml` (нет lint
и e2e), но README (раздел про публикацию своей копии) предлагает скопировать именно его. Расхождение
опишите владельцу в отчёте шага; что с ним делать — его решение.

Не входит: поиск другого неиспользуемого кода внутри файлов, переименования, перенос компонентов.

## Трудные места

Перед удалением заново убедитесь, что импортов нет: поиск по `src`, `tests`, `scripts`,
`design-system.html` и [scripts/check-design-system.mjs](../../scripts/check-design-system.mjs) — скрипт
проверки дизайн-системы может знать о прежних путях как о разрешённых.

## Приёмка

1. Файлов нет; `npm run build`, `npm run lint` (включая `design:check`), unit- и e2e-тесты проходят.
2. Поиск по репозиторию не находит ссылок на удалённые пути в документах текущего состояния.
