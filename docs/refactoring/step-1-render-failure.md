# Шаг 1. Сбой отрисовки не выводит приложение из строя

Часть [плана рефакторинга](../refactoring-roadmap.md). Общие ограничения, порядок работы и проверки описаны
там; здесь только особенности шага. Факты сверены с кодом 2026-11-14 на коммите `575e574`; номера строк
могли сместиться — сверяйте по смыслу.

## Зачем

Сейчас одно исключение при отрисовке любого экрана оставляет пользователя без приложения, и перезагрузка
не помогает: состояние, вызвавшее сбой, уже сохранено на устройстве. Единственный выход — стереть данные
сайта вместе со всеми проектами. Шаг убирает и известную причину такого сбоя, и сам класс последствий.

## Что установлено

- В `src` нет ни одной границы ошибок (`componentDidCatch`, `useErrorBoundary` не встречаются).
- «Комната» смонтирована всегда, «Расстановка» — с момента создания комнаты; обе только скрываются
  ([App.tsx](../../src/ui/App.tsx), блоки с `hidden={tab !== ...}`). «Настройка» и «Измерения» остаются
  смонтированными после первого посещения
  ([RetainedSection](../../src/ui/components/RetainedSection.tsx)). Поэтому исключение в скрытом экране
  ломает и видимый.
- `normalizeProject` в [storage.ts](../../src/state/storage.ts) проверяет почти все поля, но два пропускает
  как есть: `result: raw.result ?? null` и `scanInfo` (у него проверяется только `applied`).
- Воспроизведение (собранная версия, эмуляция iPhone в Chrome). До загрузки страницы записать в
  `localStorage` ключ `ra-draft-pending` со значением
  `{"id":"poison","name":"Проверка","room":{},"roomReady":true,"result":{"best":"x","baseline":5}}`
  и открыть приложение. Этот ключ читается при запуске раньше черновика из IndexedDB. Результат: ошибка
  `Cannot read properties of undefined (reading 'filter')`, элемента `main.content` и нижней панели
  `.tabbar` нет, видна только шапка. После перезагрузки и по адресу `#projects` — то же самое.

Вероятность в жизни низкая: нужен повреждённый или вручную правленный файл проекта либо будущая смена формы
результата подбора. Но любая будущая ошибка в отрисовке любого экрана даст тот же итог.

## Что должно получиться

**А. Проверка сохранённых данных при открытии.**
- `result` неверной формы отбрасывается (`null`, выбранный вариант — первый). Пользователь теряет только
  результат подбора, который пересчитывается кнопкой «Подобрать».
- У `scanInfo` и остальных полей, которые `normalizeProject` сейчас пропускает без проверки, неверные
  значения не должны ронять ни отрисовку, ни расчёт. Составьте в спецификации таблицу «поле → кто читает →
  какая проверка»: пройдите по `normalizeProject` и выпишите всё, что возвращается без проверки формы.
- Корректные проекты не меняются: результат настоящего подбора и проекты из существующих тестов проходят
  нормализацию без изменений.

**Б. Граница ошибок.**
- Исключение при отрисовке одного экрана не затрагивает остальные экраны, шапку, меню и нижнюю панель.
  На месте упавшего экрана — сообщение. Упавший скрытый экран ничего не показывает, пока на него не перейдут.
- Сбой в оболочке (шапка, меню, сам `App`) тоже даёт сообщение, а не пустую страницу.
- Ошибка попадает в журнал ([errlog.ts](../../src/state/errlog.ts)) с названием экрана.
- Из сообщения доступны действия, которые позволяют не потерять данные и продолжить работу:

| Где | Заголовок и текст | Действия |
| --- | --- | --- |
| Упал один экран | «Раздел не открылся». «Ошибка записана в журнал. Проект не удалён.» | «Попробовать снова», «Экспортировать проект», «Сообщить о проблеме» |
| Упала оболочка | «Приложение не открылось». Тот же текст. | «Перезагрузить», «Экспортировать проект», «Начать новый проект» (с подтверждением) |

Формулировки — предложение исполнителя оценки; владелец согласовал их отправкой команды на шаг. Если в
команде владельца указаны другие тексты или состав действий — следовать команде. Экспорт и отчёт о проблеме
уже есть в приложении («Проекты», «О приложении») — переиспользовать, не дублировать.

Сообщение строится из существующих элементов дизайн-системы по образцу «закрытых экранов»
([Gates.tsx](../../src/ui/screens/Gates.tsx): `Panel`, пояснение, кнопки). Это новый элемент: по правилам
проекта он добавляется в реестр, каталог и [docs/design-system.md](../design-system.md), тексты — в
[strings.ts](../../src/ui/strings.ts).

## Поведение

Меняется только при сбое: вместо пустой страницы — сообщение, вместо падения на неверном `result` — проект
открывается без результата подбора. Для исправных данных поведение и внешний вид прежние.

## Границы

Не входит: проверка смысла данных (диапазоны расчётных величин), смена формата или версии файла проекта,
переработка `normalizeProject`, изменение того, какие экраны остаются смонтированными (это шаг 8).

## Трудные места

- Проверка `result` должна пропускать результаты прежних версий: поля `objScore`, `subSettings`, `scheme`,
  `robust`, `notes`, `stale` необязательные ([types.ts](../../src/core/types.ts), `Placement`,
  `PlacementResult`). Слишком строгая проверка молча сотрёт пользователям рабочие результаты.
- Граница ошибок ловит исключения отрисовки; ошибки в обработчиках событий и в промисах идут мимо неё
  и уже попадают в журнал. Проверьте фактическое поведение Preact 11 для эффектов, не полагайтесь на память.
- После части А исходное воспроизведение перестаёт ронять отрисовку, и границу им уже не проверить.
  В e2e сбой можно вызвать без тестовых веток в коде приложения: через `page.addInitScript` подменить
  встроенный метод, который при отрисовке вызывает только проверяемый экран (выбрать по коду и убедиться,
  что другие экраны его не вызывают). Тестовые переключатели в рабочем коде не добавлять.

## Приёмка

1. Проект с `result` неверной формы (воспроизведение выше) открывается: видны содержимое и нижняя панель,
   «Расстановка» предлагает подбор заново, ошибок страницы нет.
2. Результат настоящего подбора после сохранения и открытия совпадает с исходным.
3. При исключении в отрисовке одного экрана остальные разделы и меню работают, на его месте — сообщение;
   «Попробовать снова» возвращает экран, если причина устранена; «Экспортировать проект» выдаёт файл,
   который затем открывается импортом.
4. Сообщение проходит `npm run design:check`, есть в реестре, каталоге и документации дизайн-системы,
   не даёт горизонтальной прокрутки на 320 и 393 px, светлая и тёмная темы.

  `scanInfo`, сохранность настоящего результата.
- e2e: сценарий с `ra-draft-pending` из воспроизведения; сценарий сбоя одного экрана; сценарий экспорта из
  сообщения.
