# Шаг 6. Сквозные сценарии без фиксированных ожиданий

Часть [плана рефакторинга](../refactoring-roadmap.md). Общие ограничения, порядок работы и проверки описаны
там; здесь только особенности шага. Факты сверены с кодом 2026-11-14 на коммите `575e574`; номера строк
могли сместиться — сверяйте по смыслу.

## Зачем

Интерфейс покрыт только сквозными сценариями (e2e): для хуков и компонентов unit-тестов нет. Шаги 7–9
перестраивают интерфейс, и e2e будет их единственной страховкой. Сценарий, который иногда падает сам по
себе, приучает не верить красному результату — или подталкивает «починить» тест вместо кода.

## Что установлено

- В `tests/e2e` 11 фиксированных пауз `waitForTimeout`:

| Где | Пауза | Назначение по комментарию |
| --- | --- | --- |
| `room.setup.ts:18`, `:23` | 800 мс | ждёт запись проекта перед снимком хранилища |
| `app.spec.ts:329`, `precision.spec.ts:36`, `room-editor.spec.ts:176`, `room-first.spec.ts:101`, `scan.spec.ts:65` | 800 мс | ждёт автосохранение |
| `room-controls.spec.ts:68`, `smoothing.spec.ts:79` | 500 мс | ждёт автосохранение |
| `navigation.spec.ts:47` | 400 мс | выяснить по коду |
| `app.spec.ts:291` | 100 мс | выяснить по коду |

  Проект записывается на устройство через 300 мс после последнего изменения
  ([useProject.ts](../../src/ui/useProject.ts)); паузы подобраны с запасом к этой задержке. В
  `specs/current-state.md` записаны прогоны 025 и 026, где под нагрузкой запаса не хватило.
- Найдена и объяснена гонка в подготовительном сценарии `room.setup.ts`. Кнопка «Настроить комнату вручную»
  ([RoomScreen.tsx](../../src/ui/screens/RoomScreen.tsx)) после перехода ставит фокус в поле глубины
  `#room-depth` через два `requestAnimationFrame`. `fill` в Playwright сначала ставит фокус в нужное поле,
  затем отдельной командой вставляет текст в поле с фокусом. Если кадры отрисовываются с задержкой, фокус
  приложения срабатывает между этими двумя действиями, и текст попадает в «Глубину» вместо «Ширины» или
  «Высоты»; «Далее» остаётся закрытой, сценарий падает по времени, остальные 79 не запускаются.
- Наблюдение 2026-11-14 на этой машине: при обычном запуске `npm run e2e` — 80 из 80 дважды и 27 из 27
  повторов подготовительного сценария; при запуске той же команды фоновой задачей — падение этого сценария
  2 раза из 2 (в «Глубине» оказалось «4», затем «2,5»).
- Для человека гонки нет: два кадра проходят раньше, чем он начнёт вводить.

## Что должно получиться

- Сценарии ждут события, а не времени: фокус в поле — перед вводом; запись проекта на устройство — по
  содержимому хранилища (например, `expect.poll` по черновику в IndexedDB через общую функцию в
  [helpers.ts](../../tests/e2e/helpers.ts)); прочее — по состоянию страницы.
- Все места, где сценарий нажимает «Настроить комнату вручную» и сразу вводит размеры, дожидаются фокуса
  в поле глубины.
- Фиксированных пауз не остаётся. Если для какого-то места условие ожидания без изменения приложения
  придумать нельзя, пауза остаётся с комментарием, почему.

## Поведение

Приложение не меняется: шаг правит только `tests/e2e`. Если окажется, что надёжного ожидания не получить
без сигнала от приложения (например, признака «проект сохранён»), остановитесь и опишите владельцу
варианты — рабочий код в этом шаге не трогать.

## Границы

Не входит: проверка в WebKit как обязательное условие публикации (сейчас задача WebKit в CI не блокирует
публикацию — это решение владельца), новые сценарии для функций приложения, смена конфигурации Playwright
сверх необходимого.

## Трудные места

- Смысл сценариев не должен ослабнуть: ожидание заменяется условием, проверки остаются теми же.
- Гонку фокуса можно воспроизвести детерминированно: через `page.addInitScript` заменить
  `requestAnimationFrame` на отложенный таймер (около секунды). До правки сценарий должен падать, после —
  проходить. Саму подмену в постоянных сценариях не оставлять.
- Снимок состояния для остальных сценариев (`tests/e2e/.auth/*.json`) делается в `room.setup.ts` после
  записи проекта: ожидание должно гарантировать, что в IndexedDB лежит уже созданная комната, иначе все
  зависимые сценарии начнут с пустого проекта.

## Приёмка

1. В `tests/e2e` нет `waitForTimeout` либо у каждого оставшегося есть комментарий с причиной.
2. Набор проходит три раза подряд при обычном запуске и один раз при запуске с отложенной отрисовкой
   кадров (фоновой задачей или с подменой из «Трудных мест» на время проверки).
3. Число сценариев не уменьшилось (80 на 2026-11-14), ни один не помечен пропущенным.
4. В `src` нет изменений.

## Проверка сверх общей

`npx playwright test --project=iphone --repeat-each=3` для изменённых файлов сценариев.
