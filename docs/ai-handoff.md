# Передача контекста между ассистентами

Room Acoustics ведут несколько ассистентов: ChatGPT, Claude Code и Codex. Контекст проекта хранится в этом репозитории, а не в переписке. Этот файл — общая точка входа: порядок чтения, текущее состояние, предпочтения владельца и порядок обновления. Правила работы с кодом обязательны и записаны в [AGENTS.md](../AGENTS.md). Если этот файл расходится с ним, действует AGENTS.md и последняя явная задача владельца.

Репозиторий: https://github.com/VictorKalevich/room-acoustics (публичный, ветка `main`). Приложение: https://victorkalevich.github.io/room-acoustics/.

## Предпочтения и постоянные указания владельца

Источник — явные указания владельца. Новое постоянное указание добавляется сюда с датой. Если это правило работы с кодом, оно добавляется и в AGENTS.md.

- **Язык.** Общение и документация на русском. Код, команды и идентификаторы — как есть.
- **Приоритет.** Последняя явная задача владельца уточняет или заменяет прежние требования. Просьба обсудить или проверить не разрешает реализацию.
- **Этапы плана измерений (с 22.11.2026).** После реализации этапа:
  - остановиться;
  - выдать отчёт по пунктам, которые задал владелец;
  - выдать пошаговую инструкцию физической проверки на iPhone 17 Pro в установленной PWA: точные названия интерфейса, минимум отдельных записей, синтетические файлы, сигналы и скрипты анализа;
  - ждать физической приёмки и отдельного разрешения на следующий этап.

  Коммит, публикация и деплой реализации этапа — только по отдельному разрешению.
- **Четыре блока оставшихся работ шумомера (22.11.2026, D53).** Блоки выполняются до физической приёмки C2, каждый — по отдельной задаче владельца. Между блоками физические испытания не требуются: все проверки, включая C2, проводятся вместе после публикации итоговой сборки в блоке 4. Непроведённые испытания не объявлять пройденными. Реализацию блоков 1–3 коммитить локально, не публиковать и не деплоить. Отложенное публиковать отдельно, только если push не публикует незавершённую реализацию.
- **Telegram Mini App (23.11.2026, D55).** Исключён из текущего цикла. Для Telegram ничего не создавать: ни SDK, ни адаптеров, ни интерфейса, ни бота, ни деплоя, ни подготовительной инфраструктуры. Задача — в отложенном; в будущем — изолированный платформенный адаптер, только по отдельной задаче владельца. Целевые платформы: PWA и Safari на iPhone, настольные и мобильные браузеры.
- **Публикация прочих задач (2026-11-16).** Если требуемые тесты прошли, ветку задачи вливают в `main` и публикуют без отдельного вопроса. Явное «Не публикуй» и правило этапов важнее.
- **Отложенное (2026-11-16).** Всё замеченное и не исправленное записывается в [deferred](../specs/deferred.md) без дублей и публикуется отдельным коммитом по процедуре AGENTS.md. Прежние записи не теряются.
- **Остановленные задачи (2026-11-16).** Если причина остановки устранена, задача продолжается в прежнем объёме без отдельной команды. Новые задачи это не разрешает.
- **Расчёты.** Формулы, частотная детализация и физические допущения меняются только по согласованной задаче. Найденную ошибку сначала описать с воспроизведением и оценкой влияния.
- **Честность проверок.**
  - Разделять три вида проверки: проверку владельца на устройстве, автотесты и собственный анализ ассистента.
  - Эмуляция WebKit не считается проверкой физического iPhone.
  - Старый прогон не выдавать за новый.
  - Непроверенное прямо называть непроверенным.
- **Совместимость.** Прежнее поведение — по умолчанию. Новое не применяется автоматически. Пользовательские данные и прежние калибровки не меняются без явного действия.
- **Калибровки.**
  - Кривую Faber не выдумывать и не синтезировать.
  - Профиль Faber и собственный профиль владельца — разные записи с происхождением и ограничениями.
  - Физического удаления профилей нет.
- **Приватность.**
  - Личные чаты, сканы, диагностические JSON и экспорты владельца не публиковать и не коммитить.
  - Переписку в документацию не копировать: только выводы и решения.
  - `docs/chat-history.md` в Git не входит.

## Как поддерживать контекст

- В конце каждой задачи и при остановке в ожидании владельца обновить раздел «Текущее состояние». Указать этап, что опубликовано (коммит), что ждёт проверки и что разрешено дальше.
- Решение владельца — в `specs/decisions.md`: что заменено и чем.
- Поведение функции — в её спецификации, `current-state.md` и индексе.
- Новое постоянное указание — в раздел предпочтений выше.
- Требования из другого чата (ChatGPT, Codex) становятся задачей, только когда владелец передаёт их как свою задачу. Переносится суть, не переписка.

## Работа в разных средах

- **Claude Code** читает `CLAUDE.md`, который подключает `AGENTS.md`. Личная память Claude Code не заменяет этот файл.
- **Codex** читает `AGENTS.md`.
- **ChatGPT** без доступа к локальной копии читает публичные файлы по ссылкам вида `https://raw.githubusercontent.com/VictorKalevich/room-acoustics/main/docs/ai-handoff.md`. Изменения в репозиторий вносятся через Claude Code или Codex.
- **Машина владельца (Windows 11, `C:\ClaudeProjects\room-acoustics`).**
  - Unit-тесты — из PowerShell: `npx vitest run`.
  - e2e: `$env:PLAYWRIGHT_CHROMIUM_CHANNEL='chrome'; npm run e2e` и `npm run e2e:safari`. Порт 4173 должен быть свободен.
  - Push — из Git Bash.
  - Деплой: GitHub Actions `Deploy to GitHub Pages` при push в `main`. Коммит с `[skip ci]` не деплоит. Задача `e2e-safari` публикацию не останавливает.
  - Версию сборки показывает меню ☰ → «О приложении»: «Версия от … (хеш)».
